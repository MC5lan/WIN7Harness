# 长任务恢复

不要凭印象继续改文件。先恢复“目标 + 现状 + 下一步”。

1. **读恢复线索**：项目记忆、`todo`/任务板、会话日志、`gitstatus`/`diff`、最近改过的文件；没有记录时先问用户“上次做到哪”。
2. **复述目标**：用 1~3 句话重述用户目标、验收标准、明确不做什么；如果与当前代码状态冲突，先指出。
3. **核对现状**：检查关键文件是否已改、构建/测试是否通过、是否有未完成的半成品；用 `read_file`/`grep` 看真实内容，不要假设上次的修改还在。
4. **列最小下一步**：只选一个能验证的下一步，先做它；不要在恢复阶段顺手扩大范围或重写已完成部分。
5. **避免重复**：如果文件已含目标改动，不要重复 apply；先 diff 确认，再决定补哪一处。
6. **更新记录**：恢复后更新 todo/项目记忆中已确认的事实；告诉用户“当前状态、下一步、需要他确认什么”。
7. **压缩后特别处理**：如果上下文被摘要过，优先保留目标、已改文件、失败命令、未完成项；细节用工具重新读取，不要凭摘要补代码。

恢复阶段的原则：**先验证，后修改；一次只推进一步。**
