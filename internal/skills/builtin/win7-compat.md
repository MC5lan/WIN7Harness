# Win7 兼容性审查

目标：不把“能在 Win10/11 跑”误当成“能在 Win7 跑”。

1. **构建底线**：程序自身必须用 Go 1.20.14、`CGO_ENABLED=0`、`GOOS=windows`、`GOARCH=amd64/386` 构建；不要引入要求更高 Go 版本的依赖。
2. **API 边界**：新增 Win32 API 前确认 Win7 导出表存在；用运行时探测 + 降级，不要直接调用 Win8+ 才有的函数。统一走现有 `pcall`/封装。
3. **文件与路径**：路径总长 ≤ 260 字符；不创建符号链接/目录联接；不依赖 `\\?\` 长路径；临时文件放 `%TEMP%` 或 `build/`。
4. **命令行**：默认 `cmd.exe`；PowerShell 2.0 可用但不保证 pwsh 7。不要用 `&&` 串联需要判断成败的多步；中文 Win7 控制台可能是 GBK，不要把乱码当代码错误。
5. **GUI**：只依赖 GDI / 16bpp 可用能力；不引入 D3D11/OpenGL/WebView2；老显卡和远程桌面要能降级。
6. **交付**：跑 `GOARCH=386` 构建、离线自检、必要时在 Win7 真机验证 DPI 100/125/150、GBK 路径、杀软拦截。
7. **输出**：列出“已验证 / 未验证 / 风险”三栏；无法在当前机器验证的项要明确说，不要假设通过。

如果用户项目明确只支持 Win10/11：按项目要求处理，但修改 WIN7 Harness 自身时仍遵守以上红线。
