# 事故排查

先保命：不要在未备份的情况下删除会话、日志、配置文件；不要反复重启碰运气。

1. **确认现象**：发生时间、操作步骤、是否必现、系统版本、32/64 位、内存档位、最近改了什么；信息不足时先问最少的问题。
2. **收集证据**：
   - 运行日志、`crash/` 下的崩溃报告与 `ui-stall-*`；
   - 数据目录、配置文件路径、模型端点/模型名（不要回显 API Key）；
   - 如果是卡死，记录是否与滚轮、输入法、截图钩子、远程桌面、杀软扫描相关；
   - 如有必要的 goroutine 栈/诊断包，直接生成并给出路径。
3. **先读再猜**：从日志最后 100 行、第一条 panic/错误、最近的代码改动看起；区分“根因”和“伴随错误”。
4. **最小复现**：用干净数据目录/最小工作区/离线模式逐项排除；一次只改一个变量，记录结果。
5. **不要做的事**：删除用户数据、清空配置、重装系统级组件、关闭安全软件来“试试看”；需要用户操作时先说明风险。
6. **输出**：现象、证据路径、已排除项、最可能根因、下一步验证；如果无法定位，给出可交给维护者的最小信息包。
7. **修复后**：补回归测试/自检项，把确认过的环境坑写入项目记忆。

注意：日志和会话可能含路径、代码、密钥片段；对外发送前先脱敏。
