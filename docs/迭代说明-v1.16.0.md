# WIN7 Harness v1.16.0 迭代说明

发布日期：2026-11-14
基线版本：v1.15.0（雪白极简）

本轮不做功能新增，只做三处交互与观感打磨：折叠动效、浅色对比度、小分辨率紧凑布局。

---

## 一、侧栏 / 检查器折叠动效

### 问题
v1.15.0 中 `Ctrl+B` 切换侧栏、顶栏按钮切换检查器都是瞬间跳变：宽度一个像素级
`a.showSide = !a.showSide` 之后下一帧就从 232 变 0，视觉上像界面被"闪"了一下。

### 实现
在 `App` 上引入动画进度量 `sideA / inspA`（0..1，float32），每帧由 `animStep()` 推进：

```go
*cur += d * 0.34        // 指数逼近
if ad < 0.02 { *cur = target }   // 收尾吸附，避免亚像素抖动
```

实际宽度由 `easeOut(t) = 1 - (1-t)^3` 映射，200ms 左右收放完成；`Timer()` 中
若本帧有变化则重算 `layout()`，其余刷新逻辑不变（Timer 本来就每帧驱动 33fps）。

首帧用 `animInit` 直接就位，避免启动时侧栏从 0 滑入的抖动。

### 关键取舍：动画期间不重排消息
朴素做法是让 `chatW` 逐帧变化，但 `layoutSession` 的缓存 key 含宽度，
宽度一变就整段全量重排——720p 老机器上每帧重排几十条消息必然掉帧。

改为把"排版基准宽度"和"可视宽度"拆开：

* `layW`：目标状态下的会话区宽度，消息、气泡、表格一律按它排版
* `chatW`：当前动画宽度，只决定绘制区被裁到哪里

效果是侧栏像抽屉滑出，内容先被裁掉一部分再逐渐露出，全程零重排。

配套调整：会话列表要窄到 64px 以下才隐藏内容（原来是 96px），
否则收尾阶段会出现"内容先消失、背景再收边"的跳空感。

### 窄窗口保护
`chatW` 原本有 320 的下限夹紧，但窗口被拖窄时夹紧只是把内容画出窗口外。
现在先算溢出量，按「检查器 → 侧栏」的顺序临时收缩（不改 `showSide/showInsp` 状态），
保证会话区至少 320px 且不溢出。

## 二、浅色选中 / 悬停对比度

v1.15.0 的浅色主题偏"白得太干净"：选中行 `#E8F0FE` 与悬停 `#F7F8FA` 在白底上几乎糊掉。

| Token | v1.15.0 | v1.16.0 | 说明 |
|---|---|---|---|
| SelectBg | #E8F0FE | #D8E5FC | 会话选中底，白底上可直接辨认 |
| CardHover | #F7F8FA | #F1F3F6 | 卡片/会话悬停 |
| AccentSoft | #EDF3FE | #DCE9FD | 强调底（按钮、图标底、补全选中） |
| TextMute | #8A919E | #7E8697 | 次要文字，对比度从 3.3:1 提到 4.0:1 |

深色主题同步提亮一档（CardHover #282C33→#2C313A、SelectBg #24334D→#2A3B59、
AccentSoft #22314F→#27385A），两套主题切换时手感一致。

补全浮层的选中项额外加一条 `Blend(AccentSoft, Accent, 0.5)` 描边，
浅底上不靠色差也能定位当前项。

## 三、1280x720 紧凑布局

`dense()` 判定为 `winH < 800`，命中时纵向间距整体收紧一档：

| 元素 | 常规 | 紧凑 |
|---|---|---|
| 顶栏高 | 46 | 40 |
| 会话行高 / 步进 | 52 / 56 | 46 / 50 |
| 消息左右留白 | 48 | 40 |
| 输入区行距 | 22 | 20 |
| 输入区内边距 | 12 | 10 |
| 输入区底距 | 12 | 8 |
| 消息段间距 | 14 | 10 |
| 空状态整体偏移 | -90 | -66 |
| 检查器段间距 | 24 | 21 |

720p 下一屏能多看到约 2 条消息，输入区与快捷卡片不再贴底。

## 五、已知限制

* 动画时长固定在 200ms 左右，未跟随系统"减少动画"设置（Win7 无该 API）
* 折叠过程中点击会话列表按当前可视宽度命中，收尾阶段（<64px）列表不可点
* 紧凑布局只按窗口高度判定，未考虑超宽屏 + 低高度组合的横向余量
