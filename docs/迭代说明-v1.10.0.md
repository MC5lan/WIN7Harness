# v1.10.0：P1 稳定性三件事（断线续写 / 失败局部回滚 / 会话压缩）+ 命令行模式

v1.9.0 解决的是"能不能连上、打字跟不跟手"，这一版解决的是"用久了会不会丢东西"：
网络半路断掉、一次改动改了一半、会话文件越堆越大。另外补上一个长期被要求的能力——
不开界面直接跑任务。

---

## 1. 流式输出断线续写

**问题**：SSE 流式输出中途被掐断（公司代理 60 秒掐连接、NAT 超时、Wi-Fi 切换），
以前的处理是整段作废：已经显示出来的几百字留在屏幕上，但没进上下文，用户只能重发，
重发又浪费一遍 token。

**做法**：
- 新增 `internal/llm/resume.go`。OpenAI 兼容协议没有"从第 N 个 token 继续"的标准做法
  （`Last-Event-ID` 各家基本不实现），所以走应用层续写：连接断了但已经收到正文时，
  把这段正文作为 assistant 消息补进上下文，再附一句明确的续写指令
  （"紧接着断点继续写完，不要重复已输出内容"），两段输出拼起来。
- `readSSE` 改成带回"本次已输出正文 + 是否出现工具调用"：工具参数只收了一半的流绝不允许
  续写——拼出来的工具调用是错的，宁可报错让上层重来。
- 补上**静默截断检测**：正常结束的服务端一定会发 `[DONE]` 或 `finish_reason`，两者都没有
  就 EOF 的，说明流被掐了。这类情况以前被当成"正常结束"，是最隐蔽的一类丢字。
- 续写只做一次，且每次都单独计时，不会被前半段的耗时吃光预算。

**验证**：`internal/llm/resume_test.go` 用 `httptest` 裸连 Hijack 模拟"吐一半就断"，
断言第二次请求带上了已输出内容与续写指令、两段正文正确拼接、用量累加；另覆盖"首包就断不续写"、
"工具调用被截断不续写"、"用户取消/鉴权失败不续写"。

## 2. 工具失败局部回滚与原子写

**问题**：两个真实事故场景——
1. 磁盘快满时 `write_file` 写一半失败，原文件已经被截断，内容直接没了；
2. `apply_patch` 一次改 5 个文件，第 4 个失败，前 3 个已经落盘，代码停在"改了一半"的状态，
   比不改更糟，而且 `/undo` 要手点 3 次才退得回来。

**做法**：
- 新增 `internal/core/atomic.go`：`WriteFileAtomic` = 同目录临时文件 → `Sync` → `Rename` 替换。
  失败最多留一个临时文件，原文件一个字节都不动。写文件、改文件、应用补丁全部改走它。
- 新增 `core.DiscardLastSnapshot()`：写失败时把刚压进去的快照丢掉，`/undo` 不会出现
  "回退了但文件没变"的空步。
- 新增 `core.RestoreLatestFor(path)`：把某个文件恢复到它最近一次快照并消耗掉那条记录。
  `apply_patch` 失败时按逆序回滚本次已写的文件，做到"全有或全无"，且只消耗自己这几条快照，
  不影响其他操作的历史。

**验证**：`internal/core/atomic_test.go` 覆盖原子写、目录不存在报错、无临时文件残留、
快照丢弃、单文件回滚（含"新建文件回滚即删除"）与"没有快照时返回 false 而不报错"。

## 3. 会话文件自动压缩

**问题**：会话是纯 JSON 存在磁盘上，聊到几百轮后单文件能到十几 MB，历史会话一多，
启动装载明显变卡，用户还经常抱怨"数据目录怎么占了几个 G"。

**做法**：
- 新增 `internal/core/compress.go`：`GzipIfSmaller` 只在压完确实更小时才返回压缩结果，
  小文件不白压；`GunzipData` 带 128MB 上限，防止畸形文件把内存吃穿。
- 会话存储加版本外壳（`version` 字段）+ 按内容自动决定是否 gzip：**读取时靠魔数识别**，
  老的无压缩会话文件不需要迁移，直接能读。
- 写入改成原子写 + 写前备份，后缀在 `.json` / `.json.gz` 之间自动切换，切换瞬间断电也不会
  出现两个半截文件；解码失败时回退到 `.bak` 并提示。

**验证**：`internal/core/compress_test.go` 覆盖阈值、往返、透传与超限；`go test ./internal/core/`
全绿。

## 4. 命令行任务模式 `-run`

**问题**：想做"每天凌晨把某个目录整理一遍"这类事，原本只能开界面手点。Win7 上也没法用
Node 那套 MCP 脚本。

**做法**：
- 新增 `internal/win32/console.go`：GUI 子系统的程序在命令行里跑时 `stdout` 是断的，
  用 `AttachConsole(ATTACH_PARENT_PROCESS)` 接回父控制台，输出才看得见。
- 新增 `cmd/win7harness/run.go`：`-run "任务"`，支持 `-dir` 工作目录、`-timeout` 超时、
  `-json` 结构化输出（含工具过程与 token 用量）、`-quiet` 只吐最终答复；
  退出码 0 成功 / 1 失败 / 2 参数错误 / 3 超时。
- 参数解析放在 `internal/core/cliargs.go`，跨平台可单测，不依赖 Windows。
- 引擎装配逻辑收敛到 `internal/bootstrap`，界面和命令行共用，避免两套配置读取各写一遍。

**验证**：`internal/core/cliargs_test.go`；386 / amd64 双架构交叉编译通过。

## 5. 崩溃可观测

**问题**：以前崩了只有一行 `PANIC` 混在日志里，用户发来求助时经常连哪一步崩的都说不清。

**做法**：
- 新增 `internal/core/crash.go`：启动写"运行标记"（PID + 版本 + 启动时间），正常退出清除；
  下次启动发现标记还在 → 上次是异常退出。提示在 `MarkRunning` **之前**算好塞进对话，
  否则第一个动作就把标记覆盖掉了，再也判断不出来。
- 崩溃时单独落一份报告：错误、栈、系统版本、**脱敏后**的配置（API Key 只留尾号）、
  日志尾部 100 行。报告目录最多保留 10 份，日志超过 2MB 自动轮转。
- 引擎跑在独立 goroutine 上，panic 会被 Go 直接抛成进程级崩溃——这里兜住，
  记录 + 落报告 + 在对话里给一句可读的错误，进程不跟着死。
- 新增 `/crash` 查看最近报告，`/crash open` 直接打开目录。

**验证**：`internal/core/crash_test.go` 覆盖异常检测、报告内容（含脱敏）、保留份数。

## 6. 顺手补的小东西

- `/rename`、`/pin`：会话改名与置顶，置顶的排在最前；`/rename` 带参数直接改，不带参数进就地编辑。
- 搜索框里回车切焦点、Esc 清空；切换会话时重置改名态与侧栏滚动。

## 升级说明

- 旧会话文件、旧配置文件全部原样可读，无需迁移。
- 会话目录会同时存在 `.json` 与 `.json.gz`，属正常现象，程序按内容自动识别。
- 命令行模式必须在命令行里带 `-run`；直接双击 exe 仍然是开界面。

## 已知限制

- 断线续写依赖模型配合"不要重复"，极端情况下仍可能出现少量重复文字，属模型行为而非拼接错误。
- `apply_patch` 的回滚基于快照，若快照目录被手动清空，失败时无法回滚（会明确报错，不会静默）。
- `-run` 模式不支持交互确认，涉及覆盖写入的任务会直接按参数执行，请先用 `-dir` 指定干净目录。
