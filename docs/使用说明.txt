WIN7 Harness v1.38.1 —— 使用说明
================================================================

一个能在 Windows 7 SP1 上跑起来的本地 AI 编程智能体。
纯 Go 单文件、零运行库依赖、自绘界面，不依赖 WebView2 / .NET / Electron。

----------------------------------------------------------------
一、安装与升级
----------------------------------------------------------------
推荐用安装包：
  WIN7Harness-v1.38.1-Setup.exe

双击后按向导走：

1. 选择安装范围
   · 仅安装给我：不需要管理员权限，装到
     %LOCALAPPDATA%\Programs\WIN7Harness
   · 安装给所有用户：需要管理员权限，装到
     C:\Program Files\WIN7Harness，公共桌面/开始菜单
   这一步只影响“标准安装”；便携安装不需要管理员。

2. 选择安装方式
   · 标准安装：装到本机，创建桌面/开始菜单快捷方式，
     可在“程序和功能”里卸载。
   · 便携安装：程序和数据放进 U 盘，不写注册表、不建快捷方式；
     换电脑插上就能用。

3. 选择位置
   标准安装默认在 LocalAppData\Programs\WIN7Harness，也可以自己选；
   普通用户不要选 C:\Program Files，除非你在上一步选了“所有用户”。
   便携安装会列出 U 盘/移动硬盘的盘符、卷标、格式和剩余空间，
   默认装到 X:\WIN7Harness；建议至少留 1 GB。

4. 安装完成后勾选“启动 WIN7 Harness”。

数据放在哪里（升级、卸载都默认保留）：
  配置          %APPDATA%\WIN7Harness
  会话/日志     %LOCALAPPDATA%\Win7Harness
  便携模式      程序目录\data（跟着 U 盘走）

卸载：
  · 标准安装：开始菜单“卸载 WIN7 Harness”，或控制面板 → 程序和功能。
  · 便携安装：直接删除 U 盘里的 WIN7Harness 文件夹即可。
  · 卸载默认保留配置和会话；想彻底清干净，手动删上面两个用户目录。

旧版 setup.bat / 绿色 ZIP：
  仍然保留，作为安装包被安全软件拦截时的备用入口。
  setup.bat 现在也把程序装到 %LOCALAPPDATA%\Programs\Win7Harness，
  并从旧的数据目录里只清程序文件，不删会话。

升级：
  · 当前用户安装 / 便携安装：程序内 /update 可下载并替换 exe。
  · 所有用户安装：装在 Program Files，普通用户不能改 exe；
    程序会提示“请运行新版安装包升级”，升级时弹一次 UAC。
  · 配置和会话在用户目录，升级不会丢。

首次启动：
  引导页三步：选接入方式、填 Base URL / API Key / 模型 ID、选工作目录。

----------------------------------------------------------------
二、界面
----------------------------------------------------------------
引导页    首次配置，之后可在设置页重新调整
聊天页    会话流：你的消息、模型输出、工具执行卡片、思考过程
设置页    左下角齿轮或 Ctrl+, 打开；顶部 6 个页签：
          模型 / 外观 / 权限 / 网络 / 预算 / 高级
          模型页可拉取端点 /models；预算页可填自定义输入/输出单价
左侧栏    会话列表，可新建、切换、删除历史会话
顶栏      会话标题右侧是工作区按钮（文件夹图标 + 目录名）：本会话用哪个目录干活
          点一下列出最近目录与"选择文件夹…"，选完只影响当前会话
输入区    右下角是模型按钮（方框图标 + 模型名）：本会话用哪个模型
          点一下向上展开模型列表，选完只影响当前会话；带绿点表示已单独钉住

【会话级模型与工作区】v1.14.0 起
    以前模型和工作目录全程序共用一份，切换要进设置页改全局。
    现在每个会话各自记一份，切会话就自动切环境，互不干扰：
      · 新建会话默认跟随全局设置，不继承上一个会话的选择
      · 在会话里切过模型或目录，就只对这条会话生效并钉住
      · 想回到全局默认：/model default、/dir default，或用下拉里的"跟随默认"
      · 全局默认仍在设置页的"默认模型 / 默认工作目录"，只影响没钉住的会话

工具执行卡片是实时的：能看到调用了哪个工具、参数是什么、输出是什么、
耗时多久、成功还是失败。点击卡片可展开完整输出。

----------------------------------------------------------------
二·五、图片输入（多模态）
----------------------------------------------------------------
现在的模型基本都支持原生识图，所以这里不再绕路：
直接把图给它，让它看图排错、看设计稿写界面、看截图复现问题。

三种方式把图片加进来：

  Ctrl+V        截图 / 复制图片后直接在输入框粘贴，立刻变成缩略图附件
                 （截图工具、微信、QQ、PrintScreen 都行）
  拖进来        从资源管理器把图片文件拖到窗口任意位置
                 （若程序以管理员身份运行，拖放会被系统拦掉，改用 Ctrl+V 或 /image）
  Ctrl+K → /image   或命令行输入 /image，弹出系统选图对话框（可多选）

松手即生效：输入框上方会出现缩略图，点缩略图把它去掉，最多同时附 4 张。
可以只发图不发字，也可以"图片 + 文字说明"一起发。

图片怎么处理（很重要，关系到会不会出错）：
  · 支持 PNG / JPEG / GIF / BMP，剪贴板里的位图（CF_DIB）直接读
  · 最长边超过 1568px 自动等比缩小，单张压到 1.5MB 以内
  · 统一转成 PNG 存到 %LOCALAPPDATA%\Win7Harness\attachments\<会话ID>\，
    文件名是内容哈希，同一张图不会重复存
  · 发请求时以 data URL 的形式随消息一起发（OpenAI 多模态协议标准格式）

纯文字对话的请求体与之前完全一致，不会因为加了图片功能而影响老模型。

如果模型不支持图片，会收到这样一条提示：
  "当前模型可能不支持图片输入……"——换一个支持视觉输入的模型再试，
  或者去掉图片只发文字。

历史会话里的图片会照常显示。为了避免长会话把上下文撑爆，
重新打开旧会话时，历史图片不会重新上传，只在文本里标注"原有 N 张图片"。
导出 Markdown 时图片会以本地绝对路径链接的形式写进去。

三、模型接入（v1.32：不内置任何厂商或模型名）
----------------------------------------------------------------
应用只承诺兼容 OpenAI 的 /chat/completions 协议。引导页只给三种接入方式：

  OpenCode Go / Go Plus   https://opencode.ai/zen/go/v1
  自定义 OpenAI 兼容端点    任何实现 /chat/completions 的地址
  本地模型                 Ollama / LM Studio / vLLM / llama.cpp

模型 ID 不再随程序内置。两种填法：
  · 直接手填服务商当前的模型 ID；
  · 点“拉取”从端点 GET /models 动态获取，再点“选择”从列表里挑。
    /models 只读元数据，不产生对话 token。

OpenCode Go / Go Plus 套餐：
  1. 在 opencode.ai/console 订阅 Go / Go Plus / Go Teams；
  2. 复制 API Key，填到“API Key”；
  3. 接口地址保持 https://opencode.ai/zen/go/v1；
  4. 模型 ID 填控制台里的原始 ID；从 OpenCode 配置里粘来的
     opencode-go/xxx 会自动去掉 opencode-go/ 前缀。
  实测 /models 可直接拉到 30+ 个模型；GPT/Grok 等原生走 Responses 的模型，
  Console 也会在 /chat/completions 上做协议转换。

内置端点只有地址，不含任何密钥。API Key 由你自己填写，
保存在本机 %APPDATA%\Win7Harness\config.json，不会上传到任何地方。
从旧版升级：已有 provider / 模型 / Key 原样保留，只补齐新的接入方式；
程序不会把你的模型名改成它猜的名字。

----------------------------------------------------------------
四、它能做什么（工具能力）
----------------------------------------------------------------
  读文件      按行读取，支持大文件分段
  写文件      新建或覆盖
  改文件      按原文精确替换，不整文件重写
  列目录      带大小、时间
  找文件      通配符匹配
  搜内容      正则搜索，返回命中行
  执行命令    受控的 cmd / powershell
  删文件      走回收站语义，危险操作强制二次确认
  跑测试      run_tests：按项目类型跑 go test / npm test / pytest / cargo test，
              失败时自动解析出失败的用例名、文件与行号，不是只丢一坨原始输出
  抓网页      web_fetch：给一个网址，取回正文（HTML 去标签转纯文本），
              带 SSRF 防护，内网地址一律拒绝
  查调用关系  calls：谁调用了这个函数、它调用了谁，改签名前先看影响面
  查表格数据  datatable：CSV / JSON 做 info / 筛选 / 求和 / 分组，不整表灌上下文
  覆盖率与基线 quality：读 coverprofile 找测试短板，benchmark 与基线比对查性能回归
  看图片      read_image：本地图片直接交给模型看（截图、设计稿、报错界面）；
              大图可按 max_side 先缩再发，ocr=true 调本机 tesseract 提文字
  后台任务    run_command 加 background=true 起任务，task_output 增量读输出、
              task_list 看清单、task_kill 连子进程一起收（Windows 走 Job Object）
  项目记忆    memory_save / memory_search / memory_list：把项目的构建方式、产物路径、
              踩过的坑记在 .harness\memory.md，以后每个会话自动带上
  补丁逐段    apply_patch 加 hunks="1,3-4" 只应用选中的改动段落，其余跳过

命令执行有一套隔离机制：每个子进程都挂进 Job Object，
超时或你点"中止"时会连同它的子进程一起干掉，不会留下孤儿进程。

【跑测试】run_tests
不用你告诉它用什么命令，它自己看目录里有什么：go.mod 走 go test，
package.json 走 npm test，pytest.ini / pyproject / tests 目录走 pytest，
Cargo.toml 走 cargo test。跑完把失败用例逐条列出（框架 + 用例名 + 文件:行号），
模型据此直接改代码，比让它自己拼命令稳。超时与用例上限都可配，避免大仓跑飞。

【抓网页】web_fetch
只抓正文不抓页面壳子：脚本、样式、导航直接丢掉，省上下文。
安全上拦住内网与云元数据地址（127./10./192.168./172.16-31./169.254./100.64.、
::1、localhost、.local），file:// 与 ftp:// 一律不受理，避免被页面诱导去打内网服务。
抓回来的正文按配置上限截断，超长内容会提示"已截断，可用分段继续"。

【项目约定】AGENTS.md
在工作目录（或其上级目录，最多向上找 4 层）放置 AGENTS.md，
内容会在每次请求时自动注入系统提示，用来固化项目规矩，例如：
    - 必须用 tabs，不要空格
    - 构建命令是 make build，测试是 make test
    - 不允许引入第三方依赖
    - 错误一律用 errors.Is 判断
输入 /init 可生成一份骨架模板。同名文件按优先级识别：
AGENTS.md > HARNESS.md > CLAUDE.md > .harness.md，越近的目录优先级越高。
约定文件总大小上限 20KB，超出部分不注入。

【目标收敛 /goal】不是跑一遍就交差
    /goal 让构建和测试全部通过
    它会先拆步骤（改哪个文件、跑什么），逐步执行；每轮结束跑一次整体验证，
    没过就把失败摘要交回去再来一轮，直到通过。三条止损：轮数上限（默认 6 轮）、
    连续两轮既没完成步骤也没让验证结果变化就停（不空转）、拆不出步骤直接拒绝。
    跑在后台，界面不卡；中途取消会保留已完成步骤。不带参数回看上一次报告。

【Git 提交与回滚】改动收得住
    /commit 走真实 git，先预检再动手：没装 git、不是仓库、仓库正在 merge/rebase、
    有未解决冲突，一律拦下说明原因，不"尽力而为"；工作区干净就不产生空提交。
    未填提交说明时按改动性质自动生成（feat/fix/docs/chore/refactor + 涉及目录）。
    改动里含 20 个以上删除或 20MB 以上大文件时先提示，由你决定。
    /rewind 在仓库里按提交回滚，未提交改动先 stash 存档（给出名字可找回），
    再 reset；提交数不够、仓库处于中间态时提前拒绝，一个文件都不动。
    没装 git 的机器自动退回文件快照回滚，功能不断档。

【并行写子任务】多个子任务同时改文件不打架
    把"改这三个互不相干的文件"拆成三个写子任务时，它们各在隔离副本里并行跑，
    跑完统一合并：一个文件只被一个子任务改就直接回写；被多个改则第一个胜出，
    其余另存为 <文件>.from-<子任务描述> 并列进报告，不静默覆盖任何产出；
    内容完全相同不算冲突；副本内的删除不回写，只记录。

【查调用关系】calls
    "改这个函数签名会影响哪些地方"、"这个行为是从哪进来的"、"这函数还有人用吗"，
    问它就行。给出定义位置、调用方清单、被调用方清单，支持 Fn / Type.Method / pkg.Fn；
    同名多个时列出候选并默认取最匹配的那个。按语法结构取调用点，注释与字符串里
    的同名不会误报。

【覆盖率与性能基线】quality
    覆盖：读 go test 的 coverprofile，给出总体覆盖率、按包拆分、低于阈值的短板清单，
    直接告诉你哪个包最该补测试，而不是只丢一个百分比。
    性能：把 `go test -bench` 的输出记成基线，下次跑完自动比对，变慢超 20% 记回归、
    变快记改进、新用例记 new。20% 容差是为了避开机器噪声，少报假警报。
    基线存在数据目录里，跨会话复用，升级不丢。

【结构化数据】datatable
    CSV / JSON 直接问，不用把整表读进上下文自己数。支持 info（列名与行数）、head、
    select（挑列）、filter（按列与运算符过滤）、sum（求和）、group（分组计数）。
    一万行表格交给程序算，模型只拿结论：既省 token，也不会算出个错数。
    带引号字段、空值、全角逗号这些脏数据在解析层消化。

【看图片】read_image
    给本地图片路径就能看：识别格式、读出宽高、把图片作为多模态内容随消息发给模型。
    截图报错界面、设计稿、图表都能直接问它。支持 png/jpg/jpeg/gif/bmp/webp，
    非图片文件明确拒绝；单张超过 8MB 只返回元信息不发送，单条消息最多 4 张。

【任务侧栏】现在做到哪了，一眼看到
    右侧常驻状态面板：进行中的目标与进度（如 3/5）、待办清单（完成/进行中/待办）、
    运行中的子任务数量。长任务不用翻聊天记录找进度；没有任务时整块收起。

【项目约定自动维护】AGENTS.md 不再靠人记着改
    每轮结束自动识别项目类型（Go / Node / Python 等，按文件特征判断），把构建、
    测试、目录要点写进 AGENTS.md 的自动区块。用标记块包裹，只更新块内内容，
    你手写的部分一律不碰；项目类型没变时不产生无意义改动。

【联网搜索】让它上网查，而不是凭记忆答
    "搜一下 Go 1.20 在 Win7 上的兼容性问题"、"查最新的 VS Code 下载地址"
    它会依次尝试多个搜索引擎，把标题、链接、摘要取回来再回答；页面抓不动时
    会如实说"没查到"，不会编一个链接出来。命中登录墙会提示你手动登录后再继续。

【工具卡折叠】长任务不再刷屏
    一条消息里连着跑了 3 个以上工具（读文件、跑命令、改代码……），这些卡会收成
    一行"执行 5 步 · 1 失败 · 1.2s"。点这一行就地展开、再点收起；
    还没跑完的工具一定逐条显示，你能看清当前卡在哪一步。
    Ctrl+Shift+T 全局切换折叠开关，/tools fold、/tools off 亦可。

【命令面板】Ctrl+K
在任何页面上按 Ctrl+K 弹出命令面板，直接打字过滤，↑↓ 选择、Enter 执行、Esc 关闭。
面板里除了全部斜杠命令，还收了几项常用动作：打开设置页、打开自检与日志、切换主题，
以及你自己放进 commands 目录的自定义命令（见下文）。不想记命令的话，用这个最快。

【提示词历史】Ctrl+R
 跨会话记住你真正发出去的提示词（斜杠命令与空输入不记），按 Ctrl+R 弹出搜索框：
 输入片段或首字母序列过滤，↑↓ 选择、Enter 回填到输入框（不直接发送）、Esc 关闭。
  历史输入保存在 %LOCALAPPDATA%\WIN7Harness\harness.kv.db，最大 200 条，重复内容自动去重。

【按键绑定】改 config.json 的 keybindings
 格式是"动作: 组合键"，例如 "historySearch": "ctrl+r"、"palette": "ctrl+k"、
 "toggleFold": "ctrl+shift+t"。支持 ctrl/alt/shift 与字母、数字、F1-F12、方向键等；
 没写的动作自动用默认值。改完重启生效。
 可配置动作：palette / sidebar / inspector / find / historySearch / newConv / toggleFold。

【斜杠命令】本地执行，不消耗 token
    /help      命令列表
    /clear     新建对话
    /compact   压缩上下文：把早期对话摘要成要点，保留最近 8 条原文
    /undo      回滚最近一次文件改动，可连续使用逐级回退
    /checkpoints  列出本会话改动过的文件清单（1 = 最新）
    /rewind N  一次回退最近 N 步改动（N 省略时为 1）；git 仓库里按提交回滚，
               未提交改动先 stash 存档再回退，失败自动退回文件快照
    /goal 目标 目标收敛循环：自动拆步骤、逐步执行、整体验证，没过就带着失败信息
               再来一轮直到通过；/goal 不带参数看上一次结果
    /init      生成 AGENTS.md 骨架
    /plan      切换计划模式：只读调研，只给方案不动手
    /diff      查看当前 git 仓库的改动清单与统计
    /commit    提交当前全部改动，信息可跟命令后，如 /commit feat: 加导出；
               先预检（非仓库 / 合并中途 / 有冲突一律拦下），未填信息按改动自动生成
    /gitstatus 查看仓库状态：当前分支、未提交改动、最近提交
    /status    查看本会话模型、工作目录、上下文占用、token 用量与费用估算
    /model     查看 / 切换本会话模型：不带参数列出可选模型，
               /model 2 或 /model qwen3-coder 直接切；/model default 回到默认
    /dir       查看 / 切换本会话工作目录：不带参数列出最近目录与默认目录，
               /dir pick 弹出系统目录选择框，/dir D:\proj 直接切，
               /dir default 回到默认工作目录

    /skill 名称  加载指定技能的正文，之后按它的流程干活
    /index     重建代码索引并显示统计；/index inc 只增量刷新改动过的文件

               /memory off 回到标准。切换即时生效，不用重启
    /export    把当前会话导出成 Markdown，可跟目标目录：/export D:\\笔记
               默认导出到工作目录下的 exports\，含思考过程与工具输出
    /mcp       查看 MCP 服务状态；/mcp reload 重连全部服务；/mcp add 一键安装
               内置模板（按提示填 Key，装完自动测连通，不用手写 JSON）
    /verify    自动验证开关：/verify on 改完代码自动跑构建与测试，失败把摘要
               交回模型继续修，最多 3 轮；/verify off 关闭；/verify 看当前状态
    /cost      成本看板：累计 token、缓存命中率、估算费用与"缓存省下多少"，
               不敲命令也能看——输入框右下角常驻一个成本 chip，点一下展开
    /resume    续做上次掉电/崩溃时未完成的那一轮（启动时也会主动提示）
    /rename    当前会话改名；/rename 新名字 直接改
    /pin       置顶 / 取消置顶当前会话（置顶的排在最前）
    /crash     查看最近的异常报告；/crash open 打开报告目录
    /stats     耗时与 token 归因：模型慢还是工具慢、各工具耗时、生成速度
    /find 词   跨全部会话全文检索（正文与工具输出都搜），多个词空格分隔需同时出现
    /open 序号 跳到 /find 结果里第 N 条命中所在的消息
    /recall 词 跨会话回忆"以前说过什么"：按会话内容时间排序，标注是你说过的
               还是它答的，可加 /recall 词 7 只看最近 7 天
    /tools     工具卡折叠：/tools fold 把连续 3 条以上已结束的工具卡收成一行，
               /tools off 恢复逐条显示；快捷键 Ctrl+Shift+T 一键切换
    /model     模型路由：/model router on 用便宜模型跑上下文压缩与只读检索，
               主对话与写文件仍用主模型；/model fast 设快速模型；/model 看状态
    /remote    手机指挥台：/remote on 开启（仅局域网），/remote code 生成 6 位配对码，
               手机浏览器打开提示的地址输码即可发指令；/remote qr 屏幕画二维码直接扫码配对；
               /remote https on|off 自签 TLS 加密；/remote approval on|off 高危操作推手机确认；
               /remote local 只监听本机，/remote off 关闭
    /loop      定时任务：/loop add 30m 跑一遍测试、/loop add daily 09:30 汇总改动、
               /loop add weekly mon 09:00 周报、/loop list、/loop del 1、/loop off 1
    /watch     目录守护：/watch add D:\proj 改动后跑测试、/watch list、/watch del 1、
               /watch gap 1 30 设防抖窗口（两次触发至少隔 N 秒，0 为不设限）
    /update    检查新版本：/update 看上次结果，/update check 立即联网查一次
    /font 120  内容字号缩放 80~200；/theme hc 高对比主题，/theme dark|light 切回
    /compare   两个会话并列对照：/compare 列出可对照的会话，/compare 3 选右侧，
               左右两栏同屏滚动，Esc 退出

【命令行任务模式】-run，不开界面直接干活
    给批处理、计划任务、流水线用：把一句话交给它，跑完把结果打到标准输出。

    WIN7Harness-386.exe -run "把 D:\data 下所有 csv 合并成 all.csv"

    常用参数：
      -run "任务"      要执行的任务描述
      -script 清单.txt 任务清单，一行一个任务，按顺序串行跑
      -dir  D:\工作   工作目录，默认程序所在目录
      -timeout 300     超时秒数，默认每任务 300，超时按失败退出
      -keep-going      某条任务失败后继续跑后面的（默认遇错即停）
      -shared          所有任务共用同一段上下文（默认每条任务互相隔离）
      -json            以 JSON 输出（含答复、工具过程、token 用量）
      -quiet           只输出最终答复，不打印工具过程

    退出码：0 成功，1 失败，2 参数错误，3 超时。
    -run 与 -script 只能二选一，同时给会报参数错误。
    从 cmd 直接双击 exe 不会进命令行模式，必须在命令行里带 -run。

【批量任务】-script，一份清单跑一串活
    WIN7Harness-386.exe -script 每日任务.txt --yes

    清单写法：一行一个任务，空行和 # 开头的行会跳过。
    D 盘中文字符的坑：记事本"另存为"请选 UTF-8；选 ANSI（GBK）会
    提示编码不对而不是拿乱码去执行。UTF-16（Unicode）也能读。

    清单里可用四个占位符，每天复用同一份文件：
      {{date}}      今天，形如 2026-11-14
      {{time}}      现在，形如 09:30
      {{datetime}}  日期加时间
      {{dir}}       当前工作目录

    示例（每日任务.txt）：
      # 早间例行
      清理 {{dir}}\temp 下超过 7 天的临时文件
      把 {{dir}}\销售 里 {{date}} 的 csv 汇总成日报.csv
      给 日报.csv 写一段 200 字的本日要点摘要

    输出：默认每条任务前打印 [2/5] 任务内容，答复逐条打到标准输出，
    结尾一行汇总（成功几条、失败几条、跳过几条、总用时、token）。
    -json 时输出 {"ok":..., "tasks":[...], "summary":{...}}。

【自检与诊断】左侧栏 ✓ 图标进入
    环境自检：一次跑完数据目录/工作目录可写、磁盘空间、模型配置、
      与模型服务的 TLS 握手、git / node / python 是否存在、系统版本、
      可用内存、界面字体，每项给出"通过 / 注意 / 失败"和修复建议。
      典型用途：Win7 上连不上模型时，先看 TLS 那一项——
      多半是缺 KB4474419（SHA-2）或系统根证书过期。
    运行日志：直接看最近 2000 行，可按 error / warn 高亮；
      可一键打开日志所在目录。
    导出诊断包：生成 zip，含环境信息、自检结果、脱敏配置（API Key
      只留首尾各 4 位）、日志、会话文件名与大小；不含对话正文，
      不含工作目录里的任何文件。出问题时把这个 zip 发给支持方即可。

【首次配置后的自动自检】
引导页三步走完，程序会在后台自动跑一次环境自检（不阻塞界面），
有问题就用提示条告诉你"几项异常"，按 Ctrl+K 搜"自检"即可查看细节。
之后每次进入自检页也会重新跑一遍。全程只读探测，不改系统设置。

【便携（绿色）模式 / U 盘安装】
安装包选“便携安装”，或手动在 EXE 同级放一个空的 portable.flag / portable.txt，
也可以双击包内的 make-portable.bat 一次性切换（再双击一次切回标准模式）。
切到便携模式后，配置、会话、快照都写在 EXE 同级的 data 目录；
如果那个目录不可写（只读 U 盘、光盘、C:\Program Files 下），程序会自动退回
标准模式（配置 %APPDATA%，会话/日志 %LOCALAPPDATA%），不会报错。
设置页右下角的版本信息会显示当前是“标准模式”“所有用户”还是“便携模式”。

U 盘密码（v1.37.0 起）：
  · 第一次在便携模式保存 API Key 时，程序会要求设置一个 U 盘密码；
  · 密码只用于加密 API Key，不保存在 U 盘上；
  · 每次启动输入一次；输错可重试，点“稍后”也能看会话，
    但调用模型前需要先在设置页或启动弹窗里解锁；
  · 忘记密码：在解锁框点“忘记密码”，清空密文后重新填 API Key；
  · 密码只保护 Key，不保护会话和代码；U 盘防丢建议用 BitLocker To Go
    或 VeraCrypt 加密整个盘。

【预算护栏】设置页或 /budget
    花费上限（美元）与 token 上限，按本会话累计计算，0 表示不限制。
    每轮调用模型前检查：达到上限即停止继续调用，不会产生新费用，
    对话里会写明原因；想继续就调高上限或直接再发一条消息。
    单价在设置页能力范围外，可由配置文件 price_in / price_out 指定
    （每百万 token），仅本地估算，不联网查询账单。

【自动压缩】
上下文超过约 9 万字符时，程序会调用模型把早期对话总结成要点，
而不是直接丢弃，避免长任务中途"忘记"前面确认过的结论。
工具输出被截断或历史被压缩时，会明确在对话里标注。

【计划模式】输入 /plan 切换
开启后只允许读文件、列目录、找文件、搜内容与待办记录，
写文件 / 改文件 / 删文件 / 执行命令会被程序直接拒绝。
适合"先看看该怎么改"的场景：让模型把方案讲清楚，确认后再退出计划模式动手。

【差异预览】
写文件或改文件前，可以把即将发生的改动以统一 diff 形式先给你看，
确认后才真正落盘。三档（配置文件 config.json 的 diff_preview）：
    large    默认，改动达到 40 行以上才弹预览，小改动不打断
    always   每次写盘都预览，最稳但最啰嗦
    off      不预览，只保留原有的大文件覆盖确认与工作区外确认

【@ 文件引用】
输入框里打 @ 会弹出工作区文件候选，↑↓ 选择、Tab 或 Enter 补全、Esc 关闭。
候选分两类：代码索引里的符号（显示为 文件:行号 + 类型与名字），以及普通文件路径。
选中符号会插入 @internal/app/pages.go:316 这样的行号引用，模型只拿到该行前后
约 40 行，不会整文件塞进上下文；也可以手写 @file.go:120-180 指定区间。
发送时被引用文件的内容会作为附件块一并交给模型，界面上仍只显示你写的原文。
单个文件上限受总预算 120KB 限制，超出或二进制文件会自动跳过。

【技能 Skills】把"这类活该怎么干"存成文件，命中就照做
技能就是一份 Markdown 流程文档，放在下面任一位置即可被自动发现
（项目级同名覆盖全局）：
    <工作目录>\.harness\skills\<技能名>\SKILL.md
    <工作目录>\.harness\skills\<技能名>.md
    %APPDATA%\Win7Harness\skills\<技能名>\SKILL.md
文件头可选一段简单属性，然后是正文：
    ---
    name: go-fix-loop
    description: Go 编译失败的定位与修复
    when: 改完 Go 代码需要验证时
    ---
    1. 先 go build ./...
    2. 读第一条错误，用 code_search 定位
    3. 小步改，改完 go test ./...
说明：
  · 技能清单会自动注入系统提示（只给名字与用途，不占上下文），
    模型判断任务匹配时会用 skill_use 工具加载正文，再照着步骤做
  · 首次启动会自动放一个示例技能 go-fix-loop 到全局 skills 目录，
    照着它改一份就是自己的技能
  · /skills 看清单，/skill 名称 手动加载
好处：常见任务的"正确做法"不用每次重复交代，也不会因为模型换了一轮就忘。

【自定义命令 Commands】把常用提示词固化成一条 /命令
 命令就是一份 Markdown 文件，放在下面任一位置即可被发现（项目级覆盖全局同名）：
     <工作目录>\.harness\commands\<命令名>.md
     %APPDATA%\Win7Harness\commands\<命令名>.md
 文件头可选属性，{{args}} / $ARGUMENTS 会替换成命令后面的参数：
     ---
     name: review
     description: 按项目规范做代码审查
     ---
     请审查 {{args}}，重点看边界条件与错误处理。
 用法：输入 /review main.go —— 正文会展开到输入框，确认或编辑后再回车发送（不会自动发送）。
   · /commands 看清单；Ctrl+K 命令面板里也能搜到自定义命令
   · 命令名只认字母、数字、下划线、中划线与中文；内置命令优先于同名自定义命令

【评测基线 Eval】把"这版到底行不行"变成数字
  · /eval 或命令行 -eval：跑 9 个不依赖模型的用例，压工具链与索引、技能底座
    （写文件逐字节正确、精确替换不误伤、补丁 dry_run 不落盘、grep 行号、
     分段读取、索引增量同步、命令输出回传、技能发现与加载、删除后一致性）
  · 报告落到 %LOCALAPPDATA%\Win7Harness\eval\eval-report.md，含通过率与失败详情
  · 通过率不是"感觉良好"，是每次发版前后都能对比的回归闸门；
    端到端（要真模型改代码）的用例留给人工/CI，不混进自动基线

【代码索引】纯本地符号索引，不需要 ctags / LSP / 联网
启动后自动在后台扫描工作区（跳过 vendor、node_modules、dist 等），
Go 源码用标准库语法树解析出函数、方法、结构体、接口、常量、变量，
Python / JS / TS / Java / C / Rust 等用轻量规则提取类与函数。
索引结果缓存在数据目录，二次启动只重解析改动过的文件（75 个文件的仓库
冷建约 60~70ms、增量约 9ms），老旧机器也不卡。
增量更新：模型每写完一个文件，程序会把该文件登记为"脏"，几百毫秒后
后台只重解析这一个文件（apply_patch 与执行命令这类改不清范围的则整库重建），
所以改完代码立刻用 code_search 查新函数，行号就是新的。
用途：
  · 输入 /index 可手动重建并查看统计，/index inc 走增量并显示
    复用/重解析/脏文件/耗时
  · @ 后输入符号名直接定位定义行
  · 模型可以调用 code_search 工具查"某函数在哪定义""这个类型有哪些方法"，
    也可以传 file 参数列出单个文件的符号大纲

【并行工具调用】
模型一次请求多个读取类操作（读文件 / 列目录 / 找文件 / 搜内容）时，
最多 4 路并行执行；写文件、改文件、执行命令仍然串行，保证顺序与确认框不乱。

【子 Agent（task 工具）】
遇到"把整个项目扫一遍""独立调研一个问题"这类会把主对话撑爆的活，
除了内置子 Agent，还可以在项目里定义自己的：<工作区>\.harness\agents\*.md，
用 markdown 头部声明 name / description / tools（工具白名单）/ model / max_rounds，
正文就是它的系统提示词。调用时用 task 的 agent 参数指名（agent="reviewer"），
工具白名单是真的裁剪——没列出的工具它调不到。输入 /agents 查看当前可用清单。

模型可以调用 task 工具派一个子 Agent 去做。子 Agent 有独立上下文，
只把结论交回来；默认只读，写操作仍要你确认；轮数上限 16，超时 8 分钟。
好处：主对话上下文不被中间过程污染，长任务更省 token。
一次可以派多个：模型用 tasks 数组一次派多个互不依赖的子任务（默认上限 3，
设置页"行为"里可调到 1~8），
全部只读时并行跑（并发数即为该上限），只要有一个涉及写入就自动退化为串行，
避免多个子 Agent 抢同一批文件、确认框互相打架。单个子任务失败不影响其他结果。

【工具钩子（hooks）】
在 config.json 里配置，可在工具执行前后自动跑本地命令，实现"改完自动格式化 / 自动跑检查"。
  "hooks": [
    {"event":"post_tool","match":"write_file,edit_file","command":"gofmt -w .","timeout":60},
    {"event":"pre_tool","match":"run_command","command":"node check.js"},
    {"event":"turn_end","match":"*","command":"echo 本轮结束"}
  ]
· event：pre_tool（工具执行前）/ post_tool（执行后）/ turn_end（每轮结束）
· match：工具名，支持 * 通配与逗号分隔多个
· pre_tool 的钩子以非零退出码结束时，本次工具调用会被阻止，输出会回给模型
· 钩子命令能读取环境变量 HARNESS_EVENT / HARNESS_TOOL / HARNESS_WORKDIR
· 输入 /hooks 可查看当前生效的钩子
· 设置页最下方"工具钩子"卡片可以直接增删：填事件 / 匹配 / 命令点"添加"即时生效，
  不用手改 JSON；每行右侧"删除"按钮一键移除

【会话导出】
/export 把当前会话整段导出为 Markdown：标题、模型、工作目录、累计 token 在头部，
每条消息按"我 / 助手"分段，思考过程收在可折叠的 <details> 里，工具调用保留名称、
参数摘要与输出（每段最多 40 行，超出注明省略行数）。
不跟参数时落到工作目录下的 exports\，文件名取会话标题加时间戳；
跟一个目录则导出到该目录。导出后自动在资源管理器里选中文件，方便直接发出去。
适合：把排查过程发给同事、贴进工单、或者留档。

【长会话性能】
消息区排版做了增量缓存：按消息记录内容指纹，只有内容变了的消息才重新解析
Markdown 与测量字形，其余整段复用上一帧的结果。流式输出时长会话不再每帧
重排全部历史，滚动与打字不掉帧。

【成本统计】
配置里填好单价（每百万 token，美元），界面 /status 会显示累计输入、输出 token 与估算费用。
  "price_in": 3, "price_out": 15
单价只用于本地估算，程序不会联网查价。

【MCP 扩展（可选）】
在 config.json 里配置 MCP 服务后，它提供的工具会自动并入工具集，模型可直接调用：
  "mcp_servers": [
    {"name":"fs","command":"npx","args":["-y","@modelcontextprotocol/server-filesystem","D:\\work"],"enabled":true}
  ]
· 启动时后台连接，连不上不影响主界面，失败原因会写在对话里
· 工具名形如 mcp_<服务名>_<工具名>，输入 /mcp 查看连接状态，/mcp reload 重连
· 需要目标机已安装 node（npx）；Win7 上 npx/pnpm 会自动经 cmd.exe 启动
· 也可以接远程 MCP，不用在本机装运行时：把 command 换成 url 即可，
  协议按 MCP Streamable HTTP（POST JSON-RPC + SSE 响应），需要鉴权就加 headers：
    {"name":"remote","url":"https://mcp.example.com/mcp",
     "headers":["Authorization: Bearer 你的令牌"],"enabled":true}
· 本地 stdio 与远程可混用，远程连接断了会显示"断开"，/mcp reload 重连

五、自检（装完先跑一次）
----------------------------------------------------------------
两种跑法，效果一样，都只在本机执行，不会上传任何内容：

1) 界面里：输入 /selftest（或按 Ctrl+K 搜"自检"，进诊断页的"端到端自检"栏）。
   后台跑，界面不卡；逐项显示 通过 / 失败 / 跳过，失败的项会给出可能原因。

2) 命令行（适合批量或远程排障）：
     win7harness.exe -selftest
     win7harness.exe -selftest --json         只输出 JSON，方便自己接脚本
     win7harness.exe -selftest --offline      没网时跳过模型连通性探测
     win7harness.exe -selftest -out D:\报告    指定报告输出目录
     win7harness.exe -selftest --keep         失败时保留现场沙箱，便于取证

评测基线（不探测模型，只看工具链有没有退化，适合发版前后对比）：
     win7harness.exe -eval                    跑一遍并打印报告
     win7harness.exe -eval --json             只输出 JSON，方便接 CI 做通过率卡点
     win7harness.exe -eval -out D:\报告       指定报告输出目录
   退出码：0 全通过 / 1 有失败 / 2 未能开始。
   跑完自动退出。退出码：0 全部通过，1 有失败，2 参数不对。

自检会真实地建目录、写文件、改文件、列目录、搜内容、执行命令、做快照再还原。
这些动作全部发生在沙箱里（<数据目录>\selftest\），不碰你自己的工作目录，
跑完自动清掉。

报告落在 <数据目录>\selftest\reports\，同一个时间点出两份：
  selftest-YYYYMMDD-HHMMSS.md    给人看的
  selftest-YYYYMMDD-HHMMSS.json  给脚本/开发者看的
老机器上遇到问题，把这两份文件回传即可复现，不用远程连机器。

当前共 77 项，覆盖文件、命令、索引、检索、验证、成本、恢复、目标收敛、Git 闭环、
并行写、基线、表格与图片等主路径。

跳过项说明：
  · 模型连通性显示"跳过"——没填接口地址 / API Key / 模型名，去设置页填完再跑。
  · Git 相关项在没装 git 的机器上显示"跳过"，装上 git 后重跑即可。
  · 渲染探测在非 Windows 上恒为跳过（本程序只在 Windows 跑，实际不会出现）。

六、安全说明（请务必读一遍）
----------------------------------------------------------------
  审批策略（/perm）把"要不要问"变成可配的规则，三层叠加：
    · 规则：allow / deny / ask 三种动作，形如 allow:run_command:git status、
      deny:run_command:format *、ask:write_file:*.env，前半是工具名，后半支持 * 通配
    · 模式：plan（只读，写盘与执行一律拒绝）/ ask（默认，写盘与执行逐次确认）/
      auto（工作区内放行，越界问，高危仍问）
    · 目录白名单：允许写工作区之外的指定目录，白名单内不再逐次确认
  判定顺序固定 deny > allow > 高危 > ask > 模式默认：deny 永远赢，
  不会因为某条 allow 写宽了就把删除放过去。
  常用：/perm 看当前策略，/perm mode auto 切模式，/perm add allow run_command:go test *
  加规则，/perm del 2 删规则，/perm test run_command "rm -rf x" 试判（不执行）
----------------------------------------------------------------
· 删除、覆盖、执行系统命令等破坏性动作，默认会弹出确认框，
  写明将要操作的**真实路径和数量**。确认后才执行。
· 设置页里"自动执行"只对读取类、低危操作生效，高危动作永远要问。
· 请给它一个专门的工作目录，不要直接把工作目录设成 C:\ 或系统盘根目录。
· 如果是别人发你的脚本、或者模型要执行你不理解的命令，先拒绝，看清楚再说。

九、常见问题
----------------------------------------------------------------
Q: 双击没反应 / 窗口闪一下就没了？
A: 打开 %LOCALAPPDATA%\WIN7Harness\harness.log 看最后几行。
   常见原因：系统缺 KB2533623，或把 EXE 放进了没有写权限的目录。

Q: 提示无法连接 / 证书错误？
A: 先确认网络能打开服务商官网；再检查是否装了 KB3140245 并启用 TLS 1.2；
   API Key 是否填错（多的空格也会失败）。

Q: 32 位系统能跑吗？
A: 能，用 WIN7Harness-386.exe。注意 32 位进程访问 System32 会被重定向，
   程序内部已做 Sysnative 处理；如果调用的工具本身是 64 位的，仍需自行注意。

Q: 历史会话存在哪？换机器怎么带走？
A: 配置在 %APPDATA%\Win7Harness，会话在 %LOCALAPPDATA%\Win7Harness；换机器时两个目录都要复制（或设置 WIN7HARNESS_HOME 统一到一个目录）。

Q: 会不会偷偷上传我的文件？
A: 不会。程序只在你发消息时把当前对话内容发给所选模型服务商，
   文件内容是否发送取决于模型调用了哪个工具、以及你是否批准。
   本地模型（Ollama / LM Studio）则完全不出本机。

Q: 老机器内存小（2G/4G），用着卡甚至崩？
A: 输入 /memory on 切低内存档（或设置页打开"低内存模式"）：
   @ 引用、工具输出、代码索引、图片尺寸与子任务并发一起收紧，切换即时生效。
   换了大内存机器再 /memory off 回去；索引规模要 /index 重建才恢复。

Q: 它能不能自己跑测试、看网页？
A: 能。让它"跑一下测试"，会走 run_tests，按项目类型自动选命令，
   失败的用例带文件名和行号列出来；让它"看下这个网址讲了什么"，会走 web_fetch，
   抓正文顺便挡掉内网地址。测试跑不起来时先确认你本机装了对应的工具链
   （Go / Node / Python / Rust），程序不替你装。

Q: 怎么卸载？
A: 用 setup.bat 装过：运行安装目录里的 uninstall.bat，或控制面板"程序和功能"卸载。
   绿色运行：删掉解压出来的文件夹即可，无注册表残留。
两种方式都不会删 %APPDATA%\Win7Harness（配置）和 %LOCALAPPDATA%\Win7Harness（会话），想清干净再手动删它们。

十、手机远程指挥台与自动化（v1.27 新增，v1.28 增强）
----------------------------------------------------------------

【手机指挥台】人在外面，让电脑上的它接着干活

  1. 电脑上敲 /remote on，界面会打出形如 http://192.168.1.7:8765/ 的地址；
  2. 敲 /remote code 取一个 6 位配对码（5 分钟有效、用一次就作废）；
  3. 手机连同一个 Wi-Fi，浏览器打开那个地址，输入配对码；
  4. 之后手机上可以看状态（模型、工作目录、当前任务进度）和发指令，
     指令进电脑的执行队列，界面里照常显示、照常记日志。

  安全边界，先说清楚：
    · 默认关闭，只有 /remote on 才监听；默认只允许局域网，/remote local 更窄（仅本机）；
    · 配对码一次性、5 分钟过期，配对成功后手机拿的是随机 token（只存哈希、落盘保存，默认 7 天有效），重启电脑不用重新扫码，随时可在「扩展页 → 设备」或 /device 吊销；
    · 手机只能发文本指令和读状态，不能点"同意"——高危操作（删文件、执行命令）
      仍然要在电脑上确认，手机上会看到"等待电脑确认"；
    · 不做公网穿透、不内置任何中转服务器。要在外网用，请自己配端口映射，
      并务必先确认密码/VPN 到位——暴露到公网的风险由你自己承担。

  想换个端口：设置页或配置文件里改 remote_port（默认 8765）。
  用完记得 /remote off，界面状态栏会显示是否在监听。

【指挥台 2.0】v1.28 新增的几件事

  · 扫码配对  /remote qr
      不用再让人念 6 位码。敲 /remote qr，屏幕上直接画出二维码（纯本地生成，
      不联网、不依赖第三方库），内容形如 http://192.168.1.7:8765/#p=配对码；
      手机相机一扫就打开指挥台并自动配对，有效期与 /remote code 一样是 5 分钟、
      一次作废。开过 HTTPS 时二维码里是 https:// 地址，手机首次访问会提示证书
      不可信，选"继续访问"即可（自签证书的正常现象）。
      窗口太窄画不下时会提示改用 /remote code 手动输码，不影响使用。

  · 手机看会话  「会话」页签
      手机页面新增「会话」页签：列出最近会话，点进去看每一轮问答和调用的工具名，
      按已读条数增量续读，不会每次从头刷。为省流量也为你省心，工具参数与
      超长输出不上手机，只看结论。

  · 手机审批  /remote approval on|off
      默认关闭，高危操作只在电脑上确认。开启后删文件、执行命令这类操作会同时推到
      手机，电脑和手机谁先点谁生效；超时没人点按"拒绝"处理，宁可不做。
      手机上只给操作摘要与影响范围，不发完整文件内容。

  · 可选 HTTPS  /remote https on|off
      开启后指挥台走 TLS，口令、指令、输出不再明文过内网。证书是程序自签的，
      首次连接手机会提示"不安全"，选继续访问即可。切换协议后已配对的手机要重新扫码
      （token 与新协议绑定）。

  · 断线重连与离线续读
      手机端记住已收到的事件序号和当前会话进度，切后台、断 Wi-Fi、锁屏回来按序号
      续传，不重复也不漏。页面顶部指示灯：绿=已连上，黄=重连中，红=断开。

【定时补跑】关机那段时间漏的任务，开机补

  开机时检查错过的排期：多次漏跑合并成一次执行，并告诉你"漏了 N 次"；
  不足一个完整周期的不补，避免每次开程序都白跑一遍。要彻底不补，
  配置文件里把 loop_catchup 设为 false。

【守护防抖】改一堆文件只跑一次

    /watch gap 1 30     第 1 条规则，两次触发之间至少隔 30 秒（默认 30，0 = 不设限）

  保存文件时编辑器常连着改好几下，以前会触发好几次。防抖窗口内的连续改动合并成
  一次执行，且这段时间的改动一条都不会丢（窗口结束时按最新状态再比一次）。

【失败自动诊断】出问题自己打包

  任务出错时会自动导出诊断包（版本、配置、最近日志、环境探测结果），并在界面上
  给出保存路径。回传问题时把那个文件发出来即可，不用再手抄环境信息。
  诊断包里不含会话正文，也不含密钥。

【桌面通知与托盘】

  窗口不在前台、或任务跑了很久时，完成后弹系统通知；托盘图标显示待办数量，
  可最小化到托盘，关窗不再等于退出程序。要真退出用托盘菜单里的"退出"。
  这两项依赖 Win32 接口，只在 Windows 上生效，云端/Linux 下自动静默降级。

【定时任务】到点自己跑

    /loop add 30m 跑一遍测试，失败就修       每 30 分钟
    /loop add daily 09:30 汇总昨天的改动      每天 09:30
    /loop add weekly mon 09:00 生成周报       每周一 09:00

  间隔最小 30 秒（更密的循环只会烧 token）；/loop list 看清单与下次触发时间，
  /loop off 1 暂停、/loop del 1 删除。任务到点开一个新会话执行，
  结果留在会话列表里，不会打断你手上正在做的事。
  关机错过的排期开机后会自动补跑（多次漏跑合并成一次，并报告漏了几次），
  详见下面【定时补跑】。

【目录守护】文件一变就动

    /watch add D:\proj 有改动就跑测试

  · 默认不限后缀（任何文件变动都算），建议用 --glob 收窄，否则日志文件会把规则刷爆：
      /watch add D:\proj --glob *.go,*.md 改动后跑测试
      /watch add D:\proj --glob *.go --ignore tmp,logs 改动后跑测试
  · node_modules、.git、.svn、vendor、dist、build、target、bin、obj 等目录默认忽略；
  · 第一次只建基线不触发，之后真有增/改/删才跑，同一状态不会重复触发；
  · 快照随规则落盘，重启后不会把整个仓库误判成"全部新增"；
  · /watch list 看规则与上次触发时间，/watch del 1 删除；
  · 触发太频繁就设防抖窗口：/watch gap 1 30（第 1 条规则，两次触发至少隔 30 秒，
    默认 30，0 表示不设限）——窗口内的连续改动合并成一次跑，一条都不会丢。

【更新检查】不打扰，但随时能查

    /update        看上次检查结果与发布说明
    /update check  立即联网查一次

  默认不带清单地址（不擅自连任何服务器）：在配置里填 update_url 指向你的
  清单 JSON 后 /update 才有意义；下载的包会校验 SHA256，摘要不符直接丢弃并报错，
  不会拿半个文件去覆盖正在用的 exe。

【看字费劲】

    /font 120      内容字号 80~200（120 就是放大 20%），超出范围自动夹回
    /theme hc      高对比主题，黑底白字加粗边框，老显示器上看更清楚
                   系统“高对比度”打开时会自动强制此主题，关闭后回到配置主题
    /compare       两个会话左右并列，改前改后对照着看，Esc 退出

  屏幕阅读器（amd64）：已暴露虚拟 MSAA 树——对话正文、输入框、发送/停止按钮
  都有名称/角色/值/位置；发送/停止的默认动作会按真实鼠标点击路径触发，
  输入框可通过辅助工具选中聚焦。386 回退窗口级标准 IAccessible。
  高对比切换不需要重启程序。

----------------------------------------------------------------
二十四、v1.31.1 性能与稳定性更新
----------------------------------------------------------------

【后台进程/界面卡死】
  · 修复窗口线程未锁定导致的随机卡死：Win32 窗口与消息循环现在固定在同一
    条 OS 线程上；此前 Go 调度器迁移主 goroutine 后，ShowWindow / WM_TIMER
    会等一条永远不会处理消息的线程，表现为启动后窗口不出现或整程序无响应。
  · 修复后台任务"永远运行中"：run_command background=true 的进程退出后，
    os/exec 最多再等 3 秒收管道，不再被继承 stdout 的孙进程拖住。
  · 新增界面看门狗：UI 线程超过 3 秒没有心跳时，自动把全部 goroutine 栈写到
    %LOCALAPPDATA%\Win7Harness\crash\ui-stall-*.txt；通知中心与诊断页能看到这些报告。
  · 出错闪退时仍会生成原有崩溃报告；现在多了一类 "ui-stall" 证据，反馈卡顿时
    直接附带该文件即可。

第二十七节 v1.32.2：工程能力“变怪”的根因修复
================================================================

这次不是模型突然变笨，而是三件环境问题把它拖进了无效试探：

1. cmd 引号路径 + 输出乱码
   - 旧实现用 exec.Command("cmd.exe", "/d", "/s", "/c", cmdline)，os/exec 会把命令串里的引号二次转义，导致 dir "D:\路径"、任何带空格/中文的路径都报“文件名、目录名或卷标语法不正确”。已改用 SysProcAttr.CmdLine 原样传命令串，前台与后台命令一起修复。
   - 中文 Win7 的 dir/where/type 按 GBK 写管道，程序按 UTF-8 读，中文路径
     变成 ????，模型以为路径坏了，反复换 dir / PowerShell / dir /x 重试。
   - 修复：run_command 现在先认 UTF-8，失败再按 GBK 解码；Go/Python/Node 的
     合法 UTF-8 输出不会被二次转码。

2. 模型不知道自己的路径
   - 系统提示现在直接给出：数据目录、全局/项目技能目录、配置文件、日志、
     程序目录。
   - skill_list 也会返回项目/全局技能目录，以及“新建技能写哪个文件”。
   - 不再需要 where /r C:\ WIN7Harness*.exe 或遍历 AppData 找自己。

3. 全盘搜索与无效命令
   - 新增命令护栏：where /r C:\、dir /s C:\、findstr /s C:\、
     Get-ChildItem -Recurse C:\ 等全盘搜索直接拒绝，并提示用 list_dir/glob
     或已知路径。
   - glob/grep 的 20000 项 / 8 秒 / 32MB 上限继续生效。

4. 工程行为约束
   - 系统提示新增：用户问“需要哪些/怎么做/有没有问题”时先给判断和方案，
     不要直接新建文件或技能；只有明确说“做/改/写/建”才动手。
   - 不顺手创建用户没要求的 skill/文档/示例；一次只交付当前要求。
   - 用户名/工作区含中文或全角括号时，cmd 的 ?? 不代表路径不存在；
     路径存在性一律用 list_dir/read_file 验证。

验证：

     若恢复时仍有请求在跑，代理变更会在下一轮发送前生效，避免并发替换 transport。

   - 386 默认约 1.2GB Go 堆上限，2GB/4GB 机器按比例收紧；amd64 按物理内存 65%。
   - 工具子进程有单进程/Job 总内存、活动进程数与 BelowNormal 优先级限制；
     如果应用本身已被启动器放进另一个 Job（Win7 不支持嵌套 Job），日志会提示，
     并继续用 taskkill /T 兜底。

6. API Key 与更新签名（v1.36.0）
   - API Key 不再明文写 config.json，改为 DPAPI 密文 api_key_enc；
     旧明文配置会在下一次保存时自动迁移。配置拷到其他 Windows 用户/机器上
     无法解密，程序会提示重新填写。
   - 支持包里的 config.redacted.json 同时清空明文 Key 与密文。
   - 更新清单支持 Ed25519 signature；正式构建：
       go run ./cmd/updatesign -gen -dir keys
       go run ./cmd/updatesign -key keys/update_private.key -in latest.json
       UPDATE_PUBKEY=$(cat keys/update_public.key) ./build.sh
     未注入公钥的开发构建跳过验签，并在日志里警告一次。
   - 详细步骤：docs/update-signing-v1.36.md

7. 渲染与消息循环（v1.36.0）
   - canvas 后端按场景差分区贴屏；WM_PAINT 不再无条件全窗口 BitBlt。
   - 窗口被遮挡/激活/改尺寸/DPI 变化时强制整块重贴，避免残留。
   - 16bpp 低色深量化只处理脏区，不再每帧重算整张 DIB。
   - 消息循环用 MsgWaitForMultipleObjectsEx：动画/流式 33fps，静止 10fps，
     不再 PeekMessage + Sleep(8ms) 空转。
   - 生命周期消息单独验收：scripts/lifecycle_check.ps1；
     页面回归：scripts/ui_regression.ps1。
   - 实测：页面回归 15/15、生命周期 4/4；Win7 静止约 10fps，
     大部分帧只用差分脏区，空闲 10 秒 CPU 增量接近 0。

8. 企业网络：PAC/WPAD、系统 CA、子进程代理（v1.36.0）
   - 应用自己的 HTTP 客户端支持按目标 URL 用 WinHTTP 解析 PAC/WPAD；
     静态代理仍优先，PAC 返回 DIRECT 时直连。
   - git/go/npm/pip/curl 子进程自动注入 HTTP_PROXY/HTTPS_PROXY/NO_PROXY。
   - 自动枚举 Windows ROOT/CA 证书库，与内置 CA、用户补充 CA 合并成
     %LOCALAPPDATA%\Win7Harness\ca-bundle.pem，并注入 SSL_CERT_FILE、
     GIT_SSL_CAINFO、NODE_EXTRA_CA_CERTS、REQUESTS_CA_BUNDLE、PIP_CERT 等。
   - NTLM 代理：自动在 127.0.0.1 启动本机转发桥，用当前 Windows 登录用户的
     SSPI 凭据完成 407 握手；LLM 与 git/go/npm/pip/curl 都可走它。
      Basic 代理和直连也会自动回退；代理提供 Negotiate 时优先 Kerberos（SPN=HTTP/<代理FQDN>），失败回退 NTLM。
   - 详细排障：docs/win7-enterprise-network-v1.36.md

第三十二节 v1.37.0：通用安装包与 U 盘密码
================================================================

1. 一个安装包，两种安装方式
   - WIN7Harness-v1.37.0-Setup.exe 由 Inno Setup 6.7.x 生成，
     同时包含 amd64 / 386，按系统位数只装对应版本。
   - 标准安装：当前用户（免管理员）或所有用户（Program Files + UAC）；

   - 便携安装：程序和数据放在 U 盘/移动硬盘的同一个文件夹，
     不写注册表、不建快捷方式；换电脑插上就能用。
   - 安装器会检测盘符、卷标、文件系统、剩余空间和写权限；
     系统盘 C:、只读盘、空间不足会明确拒绝。

2. 程序目录与数据目录分离
   - 标准安装程序在 %LOCALAPPDATA%\Programs\Win7Harness
     或 C:\Program Files\Win7Harness；数据仍在用户目录。
   - 旧 setup.bat 把 exe 装在 %LOCALAPPDATA%\Win7Harness（数据目录）里，
     新安装器/新 setup.bat 只清旧程序文件，保留 sessions、日志和配置。
   - 卸载默认不删用户数据；彻底清理需手动删除
     %APPDATA%\Win7Harness 与 %LOCALAPPDATA%\Win7Harness。

3. U 盘密码（便携模式 API Key）
   - 便携模式不再用 DPAPI（换电脑解不开），改为 U 盘密码派生密钥，
     AES-256-GCM 加密 config.json 里的 portable_secrets。
   - 格式 pwd:v1:<迭代>:<salt>:<nonce>:<ciphertext>；PBKDF2-HMAC-SHA256
     150000 次，只用标准库，不引入 x/crypto。
   - 密码不落盘、不进日志、不进支持包；每次启动输入一次。
     点“稍后”可浏览会话，但调用模型前必须解锁。
   - 忘记密码：解锁框点“忘记密码”，清空密文后重新填 Key。
   - 支持包 config.redacted.json 会清空 portable_secrets。

4. 所有用户安装的升级
   - 程序在 Program Files，普通用户不可写；
     /update apply 会先检测目录写权限，提示“请运行新版安装包升级”。
   - 当前用户/便携安装仍支持应用内下载并替换 exe。

5. 构建
   - Windows 一键：build\build-release.ps1（双架构 exe + 安装包）。
   - 安装器脚本：build\installer.iss；简体中文语言文件随仓库放在
     build\installer-lang\ChineseSimplified.isl。
   - Inno Setup 锁 6.7.x（支持 Win7）；7.x 不要用于 Win7 发布包。
   - 旧 build.sh 仍可在 Linux 交叉编译 exe；设置 ISCC 后可顺带出安装包。

第三十三节 v1.37.1：OpenCode Go 400/404 与看门狗修复
================================================================

1. OpenCode Go 会话头
   - 官方要求客户端在每次请求带稳定的 x-opencode-session（每个会话一个），
     并用真正的客户端 User-Agent，而不是通用 SDK 名。
   - v1.37.0 没带，导致 OpenCode Go 的四个模型全部返回 400：
       MissingSessionID: Request is missing x-opencode-session
   - v1.37.1 起：
       · 所有请求带 User-Agent: WIN7Harness/<版本号>
       · OpenCode Go 端点带 x-opencode-session: win7h-<会话ID>
       · /models 与聊天请求都带同一套头
   - 这不是换模型能解决的问题；升级后原来的 OpenCode Go Key 可直接用。

2. 错误信息更具体
   - 400/401/403/404/429 现在会附带上游返回的 message，
     不再只显示“请求不合法 / 接口不存在”的笼统提示。
   - 如果仍遇到 404，请把完整报错发出来；它会直接指出是路径、模型还是端点问题。

3. 界面卡顿误报
   - 系统“选择文件夹 / 选图片 / 选证书”对话框会阻塞 UI 线程；
     3 秒看门狗会把它误判成卡死并生成 ui-stall 报告。
   - v1.37.1 起，原生模态对话框期间暂停看门狗，关闭后自动恢复；
     真正的卡死仍会照常转储。

4. 升级
   - U 盘用户：把 WIN7Harness-v1.37.1-Setup.exe 放到 U 盘，运行后选“便携安装”，
     安装位置保持原来的 X:\WIN7Harness；data 目录和 U 盘密码不会动。
   - 标准安装用户：直接运行新安装包覆盖升级；配置和会话在用户目录，不会丢。

5. Key 不能混用
   - “OpenCode Go”预设只接受 opencode.ai/console 里订阅后复制的 Key。
   - 本机配置用的是 DeepSeek（https://api.deepseek.com/v1，deepseek-flash），
     它的 Key 不能填进 OpenCode Go；请在 U 盘设置里选“自定义 OpenAI 兼容端点”，
     Base URL 填 https://api.deepseek.com/v1，模型填 deepseek-flash，再粘贴 DeepSeek Key。
   - 升级后如果错误从 400 变成 401，通常就是 Key 和端点不匹配，按上面切换即可。

第三十五节 v1.38.1：输入框文字与流式收尾滚动
================================================================

1. 输入框文字颜色
   - 输入文字/占位符增加了对比度兜底：如果主题令牌和卡片底色对比度不足，
     自动退回黑色或白色，避免“浅底浅字 / 深底深字”看不清。
   - 如果仍然觉得颜色异常，请告知当前主题（浅色/深色/高对比）以及是否
     开了“兼容渲染（GDI）”，并附一张输入框截图；这类问题需要看实机像素。

2. 流式结束发白/跳顶
   - 根因：turn_end 先用上一帧 contentH 调 scrollToBottom，紧接着最后一帧
     Markdown 收尾让内容高度变化，scroll 可能落到新内容高度之外；画面只剩背景，
     滚轮一夹紧范围就恢复。
   - 修复：每帧排版后按本帧真实 contentH 夹紧 scroll；autoScroll 真正贴底；
     轮次结束/错误/停止/预算时强制整帧重绘，避免脏区在收尾帧留空洞。
   - 单测覆盖：内容变短、旧 scroll 越界、负 scroll、内容不足一屏。

3. 建议
   - 若 Win7 老显卡/16bpp/远程桌面下输入文字仍有彩边，可在
     设置 → 外观 → 兼容渲染（GDI）切换后重启对比。
