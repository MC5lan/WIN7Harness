# WIN7 Harness v1.7.0 迭代说明

基于 v1.6.0，本轮做三件事：长会话排版增量缓存、会话导出、子任务并行上限可配。
硬约束不变：Go 1.20.14、CGO_ENABLED=0、386 + amd64 双包、零依赖单文件、Win7 SP1 可启动。

## 一、长会话增量排版（内部/app）

**问题**：v1.6.0 的 `layoutSession` 每帧把整个会话重新解析 Markdown、重新测量字形。
会话上千条时流式输出会明显卡顿，因为每个 token 都要重排全部历史。

**做法**：
- `laySeg` 按消息缓存排版结果，存内容签名 + 段高 + 相对偏移的可视项。
- `msgSig` 计算消息指纹：只混角色/长度/标志位，正文采样首尾各 32 字节，
  不扫全文，保证流式时每帧成本与消息长度无关。
- `layKey` 记录会话标识、内容宽度、字号档位、是否显示思考过程；任一项变化即整段重建。
  会话标识是必须的——否则切换会话后会把上一个会话的分段套上来。
- 复用判定抽到 `core.ReusePlan(prev, cur, full)`，纯逻辑、可单测，避免这类
  "只在特定会话序列下才错"的地方只能靠肉眼。

**效果**：只有内容变化的尾段会真正重排，历史段整段复用；段高与偏移重新累加，滚动条总高仍准确。

## 二、会话导出 `/export`

- 新增 `core.RenderSessionMarkdown`：纯函数，输入元信息 + 消息，输出 Markdown。
  头部含标题、导出时间、模型、工作目录、累计 token；正文按"我 / 助手"分段，
  思考过程收进 `<details>` 可折叠块（超 1200 字截断说明），
  工具调用保留名称、中文短名、参数摘要与输出（每段最多 40 行，超出注明省略行数）。
- `app.ExportConv` 只做数据转换与落盘：默认导出到工作目录下 `exports\`，
  未设工作目录时落到 `%APPDATA%\WIN7Harness\exports`；文件名取会话标题 + 时间戳，
  非法字符剔除并限长 40 字（`core.SafeFileName`）。
- `/export` 命令与 Ctrl+K 命令面板同步登记，导出后自动在资源管理器选中文件。

## 三、子任务并行上限可配

- `core.Config` 新增 `max_sub_tasks`，默认 3，`Normalize` 收敛到 1~8（老配置自动补默认值）。
- `agent.Engine.MaxSubTasks` 透传到 `tools.Context`，`task` 工具按实际上限校验与限流；
  并发用信号量限制在同一上限，不再写死"一次全放出去"。
- 设置页"行为"卡片新增 `- N +` 步进控件，保存时写盘并重建引擎。
- 工具描述不再写死"最多 3 个"，改为"默认 3，可在设置里调到 8"，避免与实际配置不符。

## 五、仍未覆盖（下一轮候选）

1. **Win7 真机验证** —— 从 v1.4 挂到现在，Linux 环境无 wine/qemu，只能做编译期与单测保障。
   需要人工在 Win7 SP1 + KB2533623 + KB4474419 上跑一遍启动、TLS 握手、命令执行、钩子。
2. 增量排版只有逻辑层单测，布局相关的真实帧耗时必须在 Windows 上测；
   建议加一个内置"性能探针"命令，输出 N 条消息下的 layout 耗时。
3. 导出仅 Markdown，HTML / 纯文本未做；导出大文件（含工具长输出）没有体积提示。
4. 非 Go 语言的代码索引仍是正则级，不够精确（v1.6.0 遗留）。
5. 钩子不能就地编辑，只能删了重加。
