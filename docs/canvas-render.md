# 面板渲染后端：canvas 矢量光栅接入

改造目标：把面板从"纯 GDI 硬边绘制"升级为"几何矢量抗锯齿 + GDI 文本"的混合渲染，
同时不改动 17 个文件里 46 处业务绘制调用点，并保证低端 Win7 机器上的帧成本不升反降。

## 1. 开关与回退

**默认 canvas**（v1.29.1 修复后）。几何走矢量光栅、文本仍由 GDI 画；
显式设 `gdi` 可一键回退到旧路径，无需重编译。此前聊天页空白的根因与修复见第 8 节。

| 取值 | 后端 | 说明 |
| --- | --- | --- |
| 未设置 / `canvas` / `on` / `1` / `true` | canvas（默认） | 几何走矢量光栅，圆角带抗锯齿 |
| `gdi` / `off` / `0` / `false` | GDI | 回退路径，圆角硬边、无抗锯齿 |

```
rem 默认：直接启动（canvas）
win7harness.exe
rem 回退到 GDI
set WIN7H_RENDER=gdi
win7harness.exe
```

启动时日志会写一行 `渲染后端: canvas（屏幕色深 32bpp, 缩放 1.00）` 或
`渲染后端: gdi（...）`，真机验收先看这行确认生效。显色异常时设 `WIN7H_RENDER=gdi` 即可回退。

## 2. 三层结构

```
业务代码 (app/, ui/layout.go …)   ← 零改动
        │  FillRect / Round / RoundStroke / Line / Dot / Ring / Gradient / Clip / DrawImg
        ▼
Canvas 门面 (ui/gfx.go)           ← 只加一层 if c.render() 分支
        │  转成物理像素后追加 rxCmd
        ▼
命令流 + 脏区 (ui/rx.go)          ← 与平台无关，Linux 可单测
        │  rxDirty 求脏区 → renderRegion 只重放这一块
        ▼
DIB 后备位图 + GDI 文本 (ui/gfx_canvas.go)
```

### 2.1 命令记录

`FillRectP / Round / RoundStroke / Line / Dot / Ring / Gradient / Clip / DrawImg` 在
canvas 模式下不再直接调 GDI，而是往本帧命令流追加一条 `rxCmd`（物理像素坐标），
并带上当前裁剪矩形。`Measure / MeasureFace / LineHeight` 属于纯查询，仍走 GDI 即时返回，
因此**布局计算与改造前完全相同**，不会出现"换了后端按钮就错位"。

### 2.2 脏区与增量重放

每帧 `Flush` 时把本帧命令流与上帧比对，只重绘差异区域：

- 先求公共前缀、再求公共后缀，取中间那段的像素并集；
- 只算前缀是不够的——面板里点中一项会往命令流**中间**插一条高亮命令，后面所有命令
  下标整体后移，前缀比对会从插入点一路算到末尾（实测脏区 86.9%）。加上后缀比对后，
  同样的场景脏区降到 2.8%；
- 旧命令被删掉时，旧命令占过的像素也必须并进脏区，否则会残留残影；
- 脏区最终与画布求交，不会越界。

### 2.3 合成与文本

`renderRegion` 把命令流重放到脏区大小的离屏 RGBA 上（`rasterizer.FromImage` +
`CartesianIV` + `DPMM(1.0)`，1 单位 = 1 像素），按预乘 alpha 合成到全帧缓存，
再转成 32bpp top-down BGRA 写回 DIB。

文本不参与矢量光栅：写回 DIB 后，用原来的 `TextOut / DrawText` 把**落在脏区内**的
文本命令按记录时的裁剪重放一遍。字体、字号、对齐、省略全部复用旧调用，
排版度量与改造前一致，不会因换后端抖动。

## 3. 实测数据（1280×800，仿真面板）

| 帧 | 脏区 | 占屏 | 光栅耗时 |
| --- | --- | --- | --- |
| 首帧（全量） | 1280×800 | 100% | 26.1 ms |
| 静止帧 | 0×0 | 0% | 0.14 µs |
| 单点悬停变化 | 186×156 | 2.8% | 1.34 ms |

全量帧 26 ms 与改造前 GDI 全量重绘（实测 123 ms 量级，见接入方案文档）相比更快，
原因是 GDI 的 `RoundRect/Ellipse` 在深色面板上要多次填充+描边，而矢量光栅只做一次覆盖。

## 4. 体积代价

| 构建 | amd64 exe |
| --- | --- |
| 空 Go 程序 | 0.82 MB |
| 链接 canvas 光栅器 | 4.50 MB |
| 本程序（改造后） | 11.2 MB |

即 canvas 带来约 **+3.7 MB**。这是一个 exe 便携包的代价，可接受但需要知情。
若要回到 7.5 MB 量级，可把 `gfx_canvas.go` 的 build tag 改成 `windows && canvasrender`、
给 `rx.go` 的光栅部分加同 tag 并补一个 `!canvasrender` 桩，即可做成编译期裁剪；
当前保留运行时开关，优先保证"同一个 exe 能现场切换、现场回退"。

## 6. 已知限制

1. **文本层级是近似的**。文本统一在几何之后重放，若某处先画文字、再用不透明图形盖住它，
   canvas 模式下文字会浮在图形之上。面板代码目前都是"先底后字"，未触发该情况；
   如遇异常可用 GDI 回退确认。
2. **渐变只支持水平/垂直**，与原来 `GradientFillRect` 的能力一致，没有扩展。
3. **无模糊**。发光/阴影仍靠多层半透明描边近似，canvas 快照版没有滤镜。
4. **文本脏区按字符数×字号×1.35 估算**，偏保守；极端窄字体会多刷一点面积，不会漏刷。

## 7. Win7 真机验收清单

1. 不带环境变量启动，日志应出现 `渲染后端: canvas`（这是默认路径）。
2. `set WIN7H_RENDER=gdi` 后启动，日志应出现 `渲染后端: gdi`，作为对照。
3. 看圆角卡片、圆环状态点、分割线：边缘应平滑无锯齿。
4. 鼠标在左侧列表上下移动，高亮块跟手，无残影、无闪烁。
5. 滚动长对话：文字不抖、不重影、行高与旧版一致。
6. 拖动窗口改变大小、切到 125% 缩放：布局不跑位。
7. 若显色异常，设 `WIN7H_RENDER=gdi` 回退 GDI，并把日志与截图留档。

## 8. 已修复：聊天页内容区空白（2026-11-15）

**现象**：引导页正常，聊天页内容区几乎全白，只剩顶栏与一小行文字，滚动后连文字也消失；
日志无 PANIC。截图存于 `fix-v1.29.1/selfcheck/`（修复前）与 `fix-v1.29.1/redesign/`（修复后）。

**定位过程**：逐帧导出光栅器输出与后备位图（DIB）比对。光栅器本身画得完整；
问题出在 DIB——第 1~3 帧正常，第 4 帧起被整片刷成背景色，而 canvas 只把"脏区"（常常只有
10×10 的呼吸点）的几何写回，于是大片区域保持纯色。

**根因**：`gfx.go:FillRect`（逻辑坐标版本）漏了 canvas 分支，仍直接调用 `win32.FillRect`
把背景画到 GDI 位图上。聊天页每帧用它铺满整个窗口（`app.go` 中多处），
而 `FillRectP` / `Round` / `Line` 等都走命令流。两者混用导致 DIB 与命令流状态不一致。

**修复**：
1. `FillRect` 统一转调 `FillRectP`，所有几何都进命令流；
2. `flushCanvas` 在"命令流完全一致"的早退分支也要 `rx.scene.reset()`，
   否则下一帧会继续往同一条命令流里追加。

修复后逐帧 DIB 非背景像素占比恒定（0.696%），聊天页、引导页、深色主题与多尺寸窗口
在 canvas 下均完整，滚动无残影，零 PANIC。据此把默认后端切回 canvas，
`WIN7H_RENDER=gdi` 保留为现场回退入口。
