WIN7 Harness v1.23.0 迭代说明
================================================================

版本定位：把"能改代码"补成"改完能自己验、断了能接着干、花钱看得见"。
承接 v1.22 的测试闭环（run_tests），这一版把验证、恢复、成本三条线做成闭环，
并清掉了界面上遗留的四项毛病。

适用环境不变：Windows 7 SP1 + KB2533623 + KB4474419，单文件 exe，零运行库依赖。
双架构包：WIN7Harness-1.23.0-x86.zip / WIN7Harness-1.23.0-x64.zip。

----------------------------------------------------------------
一、P0 三项
----------------------------------------------------------------

1. 验证闭环自动串联（/verify）
   过去：模型改完代码就宣布完成，是否正确要用户自己跑一遍。
   现在：一旦本轮出现写文件/改文件/跑命令，轮次结束时自动跑项目自带的验证
   （go build + go test / npm test / pytest / cargo test，按项目类型识别），
   失败则把"失败用例名 + 文件:行号 + 关键报错"灌回模型继续修，最多 3 轮。
   反循环设计：只读问答不触发；同一轮不重复跑同一命令；超过 3 轮直接停手并
   把未解决的问题原样报给用户，不假装成功。
   开关：/verify on|off，环境变量 W7H_VERIFY=1 亦可，默认关闭（避免非代码任务
   白跑构建）。

2. 崩溃与断电恢复
   过去：程序被强杀或断电，这一轮的上下文全丢。
   现在：core.Journal 在三个时机增量写盘——发消息时（起点）、每个工具结束时
   （进度）、轮次结束或出错时（收尾）。下次启动扫到"Started 但没有 Finished"
   的轮次，就提示上次的原始请求与最后一步工具，/resume 直接接着做。
   取舍：只在工具边界落盘，进程内不做每 token 刷写，避免把 SSD 写爆；
   代价是极端情况下丢最后一个工具的结果，恢复提示里会明确说明。

3. 工具输出智能摘要
   过去：超预算直接截断，报错行常常正好被切掉，模型拿着半截日志瞎猜。
   现在：先在本地做摘要——保留错误行、FAIL/失败用例、文件路径与行号等关键行，
   头尾各留一段上下文，中间用省略标记；摘要后仍超预算才截断，并在返回里标注
   "已裁剪"。未超预算时原样返回，diff 与结构化输出不受影响。
   压缩后单行极长的 JSON/base64 走字符窗口截断，避免把逻辑单元切碎。

----------------------------------------------------------------
二、P1 三项
----------------------------------------------------------------

4. 提示缓存与成本看板（/cost）
   系统提示、AGENTS.md、历史消息保持稳定前缀，不让时间戳一类可变内容混进去，
   以命中服务端 prompt caching；usage 里解析 prompt_cache_hit_tokens 等字段，
   统计累计命中率与最近一轮命中率。
   看板给出：模型、轮数、输入（含命中）、输出、缓存写入、命中率、估算费用、
   "全未命中需要多少、缓存省下多少"，并区分"价目表精确命中"与"默认价估算"。
   入口三处：/cost 看板、/stats 摘要行、输入框右下角常驻成本 chip（可点开看板，
   设置里可关）。命中率为 0 时直接给排查方向，而不是让用户盯着 0 发呆。

5. 索引内存峰值
   大仓库后台重建时同时持有新旧两份符号表，是"内存突然翻倍"的根源。
   现在：文件集合、mtime、大小全未变时直接复用上一份快照，不再重建；
   变了则按上次符号数预分配容量（避免 append 反复扩容的瞬时双份），
   并对符号预算做硬夹取。构建统计输出驻留内存估算与本次生效预算，
   /index 与自检都能看到。

6. MCP 一键装（/mcp add）
   过去：加一个 MCP 服务要手写 JSON，命令、参数、env 稍有差错就连不上。
   现在：内置模板目录（文件系统、Git、SQLite、GitHub 等），输入编号选模板，
   按提示填空（目录、Token），敏感值只进环境变量、不出现在命令行与日志里，
   拼装完立刻起进程测连通，失败给出具体原因（缺命令、超时、鉴权失败）。
   已装检测按 ID 比对，重复安装会提示而非再塞一份。

----------------------------------------------------------------
三、P2 界面遗留四项
----------------------------------------------------------------

7. 抽屉关闭按钮
   侧栏与检查器抽屉右上角补关闭按钮，点空白处关闭的行为保持不变。

8. DPI 变更回退
   拔插外接显示器、改系统缩放后重新探测 DPI；探测值不合理（0 或超出范围）
   时回退到上一个可用比例，不再出现整个界面糊掉或错位。

9. PrintScreen 框选截图
   全局低级键盘钩子拦 PrintScreen，冻结整屏后进入框选：未选区压暗、白色选框、
   尺寸提示条；松手裁剪（32bpp DIB 归一化 + 视觉坐标换算），结果进附件、
   同时复制到剪贴板。输入区也加了截图按钮，不记快捷键也能用。

10. 16bpp 偏色
    远程桌面与老显卡常把色深降到 16bpp，自绘界面直接贴图会出现色带与偏色。
    现在按 565 量化 + 4x4 Bayer 有序抖动，逐行并行处理，只在低色深时启用，
    32bpp 下零开销。

----------------------------------------------------------------
四、质量与发版
----------------------------------------------------------------

· 单元测试：go test ./... 全绿；新增 dibutil（选区归一化、裁剪、行序）、
  summarize（摘要保关键行、预算内直通）、budget/cost、codeidx 内存用例。
· 自检 32 项：v1.22 的 25 项全保留，新增 ST26 验证闭环、ST27 崩溃与断电恢复、
  ST28 工具输出先摘要再截断、ST29 提示缓存与成本看板、ST30 索引内存峰值、
  ST31 MCP 一键装模板、ST32 截图选区裁剪。
  取向：造真实数据走主路径，断言可观测结果（落盘日志、字节数、像素坐标），
  不用"函数存在"凑数。
· 评测 9 项：不依赖模型的工具链基线照旧全绿，用于防止发版退化。
· 交叉编译：Go 1.20.14，GOOS=windows GOARCH=386 / amd64，产物做 PE 头校验。
· 兼容性：配置新增 verify_mode / cost_board 两个可选字段，旧 config.json 直接
  可用；会话文件格式未变。

----------------------------------------------------------------
五、已知取舍
----------------------------------------------------------------

· 自动验证默认关闭：开着的代价是每次改代码都跑一遍测试，小项目无感，大项目
  可能几十秒。建议在代码项目里 /verify on，写完一版再 off。
· 恢复只到工具边界：进程内不做每 token 落盘，极端断电会丢最后一个工具的结果。
· 成本为本地估算：按内置价目表折算，仅作趋势参考，以服务商账单为准。
· 低色深量化是有损的：16bpp 下颜色精度本来就有限，抖动换来的是没有色带，
  不是还原真彩。
