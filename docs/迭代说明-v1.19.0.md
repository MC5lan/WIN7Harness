# WIN7 Harness v1.19.0 迭代说明：端到端自检与真机验证闭环

## 一、这一版解决什么

竞品评估里最关键的一条差距不是功能数量，而是**我们没有任何可复现的验证基线**：
v1.18 及以前的"自检"只是环境探测（目录、磁盘、模型、TLS、外部命令），
它回答的是"环境看起来对不对"，回答不了"功能到底通不通"。

老机器上复现问题靠对话描述，来回几轮才能定位一个路径编码或确认逻辑的毛病。
v1.19 把这条链路补成闭环：**跑一次 → 出报告 → 回传两个文件 → 直接定位**。

## 二、端到端自检（internal/selftest）

16 项用例，全部真调工具集与 core 能力，不是桩调用：

| 编号 | 用例 | 验的是什么 |
| --- | --- | --- |
| ST01 | 工具注册完整性 | 11 个工具一个不少、名字与 schema 齐全 |
| ST02 | 数据目录可写 | `%APPDATA%\Win7Harness` 真能落盘 |
| ST03 | 沙箱磁盘读写 1MB | 老机械盘下的基本吞吐 |
| ST04 | 写入后读回（中文） | 中文正文往返不失真 |
| ST05 | 精确替换唯一匹配 | edit_file 的锚点语义 |
| ST06 | 目录列举与通配符 | list_dir / glob 的匹配规则 |
| ST07 | 内容检索命中 | grep 的行号与上下文 |
| ST08 | 符号检索命中 | 代码索引在真实文件上能建能查 |
| ST09 | 命令执行与输出捕获 | run_command 的 stdout/stderr 与退出码 |
| ST10 | 系统目录写保护 | 往系统目录写必须被拦 |
| ST11 | 危险命令分级 | `format` / `del /s` 这类要落到高危 |
| ST12 | 快照与还原 | 改坏能退回上一版 |
| ST13 | 原子写与压缩往返 | 断电安全写 + gzip 往返一致 |
| ST14 | 中文与空格路径读写 | `C:\我的 项目\测试.txt` |
| ST15 | 渲染环境探测 | 色深 / DPI / 字体，16 位色与缺雅黑给提示 |
| ST16 | 模型连通性 | 真发一次 Ping，区分"没配"与"配了不通" |

每项带超时（默认 40s）与 recover：**单条崩溃或卡死不拖垮整轮**，记为失败并继续。
用例跑在沙箱里（自检参数 `WorkDir` 缺省时自动建临时目录），跑完清理，
不碰用户工作区；`--keep` 可保留现场。

## 三、三个入口

### 1. 命令行（接批处理 / CI）

```
win7harness.exe -selftest                  # 跑完即退
win7harness.exe -selftest --json           # 只输出 JSON
win7harness.exe -selftest --offline        # 无网跳过 ST16
win7harness.exe -selftest -out D:\报告      # 指定报告目录
win7harness.exe -selftest --keep           # 失败保留沙箱
```

退出码：`0` 全绿，`1` 有失败，`2` 参数不对（与 `-selftest` 同时给 `-run` 也归 2）。
命令行模式不占单实例互斥量、不初始化界面与字体，可与其他实例并存。

### 2. 界面：`/selftest` 或诊断页"端到端自检"栏

后台 goroutine 跑，跑的时候界面照用；逐项显示状态、耗时、失败原因与建议；
完成后 toast 汇报，一键打开报告目录。诊断页现在三栏：环境自检 / 运行日志 / 端到端自检。

### 3. 安装脚本提示

`setup.bat` 装完会提示跑一次 `-selftest`，报告落点一并写在屏幕上。

## 四、报告格式

落盘 `<数据目录>\selftest\reports\`，同一时刻出两份，文件名带时间戳不互相覆盖：

- `selftest-YYYYMMDD-HHMMSS.md` —— 给人看：逐项状态 + 失败原因 + 修复建议
- `selftest-YYYYMMDD-HHMMSS.json` —— 给脚本：机器可读，便于后续自动比对基线

报告头带版本、OS/架构、沙箱路径、时间与总耗时，末尾是"通过 N / 失败 N / 跳过 N"
与通过率（跳过不计入分母）。判断逻辑：**有失败或有整体错误才退出非 0**，
跳过不算失败 —— 未配模型的机器不该被判定为"不能用"。

## 五、越界保护补强（顺手修的一处真问题）

写用例 ST10 时发现旧逻辑有漏洞：`ResolvePath` 在非 Windows 上按 `\` 会解析错，
且写文件类工具只查了 `IsForbiddenPath`（系统目录），**没有判定"跳出工作区"**。
结果是 `..\..\` 这类相对路径在未确认时也能写出去。

这一版：

- `core.ResolvePath` 按 `os.PathSeparator` 分支，Windows/非 Windows 各自正确
- 新增 `core.EscapesWorkDir(workDir, resolved)`，先 `filepath.Rel` 归一化再判定
- `write_file` / `edit_file` / `delete_path` / 打补丁工具 在系统目录检查之后，
  统一追加越界检查：目标跳出工作区且未获确认 → 拒绝并说明原因

## 六、验证方式（本轮实际执行）

- `go test ./internal/core/ ./internal/tools/ ./internal/selftest/` 全绿
- `GOOS=windows GOARCH=386/amd64 CGO_ENABLED=0 go build` 双架构通过
- `build.sh` 全量出包：图标 9 档校验、PE 结构校验（x86=PE32 / x64=PE32+）、
  资源校验（RT_ICON=9、RT_GROUP_ICON=1）、ZIP 6.20 MB
- 报告可读性用本机 `selftest.Run` 实跑校验：16 项中 14 通过 2 跳过（Linux 无 GDI、
  未配模型），Markdown 47 行，退出码 0

## 七、下一版（v1.20）接什么

按既定路线：plan mode（先出计划再动手）+ 失败诊断注入（把工具报错原文回灌给模型，
而不是让它猜）+ checkpoint（关键改动前自动打点）。自检这层地基已经铺好，
v1.20 每加一个能力，就往 selftest 里补一条对应用例，避免再次出现"功能加了但没人验"。

## 八、已知限制

- ST15 渲染探测仅在 Windows 下有效，其他平台恒为跳过
- ST09 命令执行依赖系统 `cmd.exe`；被组策略禁用命令行的机器上会失败，
  报告里会写明是策略问题而不是程序缺陷
- 自检不会去连真实 API 做完整对话（只 Ping），避免消耗额度；完整链路请用 `-run` 验一次
