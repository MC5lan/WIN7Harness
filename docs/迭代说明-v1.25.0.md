WIN7 Harness v1.25.0 迭代说明
================================================================

版本定位：把"单轮对话里的助手"补成"能自己盯住一个目标、改动能提交能回滚、
多个子任务能同时改文件"的工程执行体。
v1.24 解决了信息从哪来、报错怎么定位、钱怎么省；这一版解决三件更硬的事：
目标能不能收敛（不是跑一遍就交差）、改动能不能收口（提交与回退）、
并行子任务会不会互相踩（隔离副本 + 合并），外加把"调用关系 / 覆盖率与性能 /
表格数据 / 图片"这几类高频信息补进工具层，并让项目约定自动沉淀、任务状态常驻侧栏。

适用环境不变：Windows 7 SP1 + KB2533623 + KB4474419，单文件 exe，零运行库依赖，
不装 .NET、不装 VC++、不写注册表。
包名：WIN7Harness-v1.25.0-win7.zip（内含 x86 / x64 双架构 exe、README、setup.bat）。

----------------------------------------------------------------
一、P0 —— 目标收敛、改动收口、并行写
----------------------------------------------------------------

1. 目标收敛循环（/goal 目标）
   过去：一句话交代任务，模型跑一轮就交差；测试没过也只是"我改完了"。
   现在：/goal 进入 Plan → Exec → Verify 循环：先让模型把目标拆成可执行步骤，
   逐步执行；每轮结束跑一次整体验证（构建 + 测试），没过就把失败摘要交回去，
   带着失败信息再来一轮，直到验证通过或触发止损。
   止损三条，防止无限空转：
     · 轮数上限（默认 6 轮，可配）；
     · 停滞判定：连续两轮既没有步骤完成、验证结果也没变化，立刻停（stalled），
       不拿用户的时间去试运气；
     · 拆不出步骤直接拒绝执行（no-plan），而不是硬着头皮乱改。
   运行在后台线程，界面不卡；Ctrl 级取消落到 cancelled，已完成步骤保留在报告里。
   报告含每轮做了什么、验证原话、最终停在哪一步，可用 /goal 无参回看上一次结果。

2. Git 提交与回滚闭环（/commit、/rewind、/gitstatus）
   /commit 走真实 Git：先预检再动手。
     · 没有 git、不是仓库、仓库正在 merge/rebase（把中间状态提交上去是灾难）、
       存在未解决冲突 → 一律拦下并说明原因，不"尽力而为"；
     · 工作区干净直接告知，不产生空提交；
     · 有改动才开始 add + commit，未填说明时按改动性质自动生成
       （feat/fix/docs/chore/refactor 前缀 + 代表性目录），不是"update"；
     · 改动里含 20 个以上删除或 20MB 以上大文件，提交前提示，交由用户判断。
   /rewind 在 Git 仓库里按提交回滚（git reset --hard HEAD~N），并按序保护现场：
     先把未提交改动 stash 存档（给出 stash 名，可找回），再回退；
     仓库进程中间态、提交数不足 N 时提前拒绝，一个文件都不动。
   Git 不可用或不是仓库时，自动退回原有的文件快照回滚，功能不断档。
   /gitstatus 一行看全：分支、未提交改动、最近提交。

3. 并行写子代理（task 多写子任务）
   过去：拆三个子任务各改一个文件，实际串行执行，慢且互相看到半成品。
   现在：写类子任务各自在隔离副本里跑，跑完统一合并回工作目录。
   合并规则刻意保守：
     · 一个文件只被一个子任务改 → 直接回写；
     · 被多个子任务改 → 第一个胜出，其余另存为 <文件>.from-<子任务描述>，
       冲突条目写进合并报告——不静默覆盖任何人的产出；
     · 内容完全相同（比如两个子任务都只做格式统一）不算冲突，免得多出一堆副本；
     · 副本内的删除不回写，只记录，避免一个子任务的误删波及全局。

----------------------------------------------------------------
二、P1 —— 调用关系、覆盖率与性能基线、结构化数据
----------------------------------------------------------------

4. 调用关系检索（calls 工具）
   给一个函数名，回答两件事：谁在调它（callers）、它调了谁（callees），
   顺带给出定义位置、同名候选提醒。
   用途：改函数签名前先看影响面；定位某个行为的入口；判断死代码。
   比 grep 准的地方在于按语法结构取调用点，注释里出现的同名、字符串里的同名不误报。
   符号支持 Fn、Type.Method、pkg.Fn 三种写法；同名多个时明示候选并默认取最匹配的一个。

5. 覆盖率与性能基线（quality 工具）
   两件事合成一个工具，都基于 go test 的真实输出：
     · cover：解析 coverprofile，给出总体覆盖率、按包拆分、低于阈值的短板清单，
       直接指出"哪些包最该补测试"，而不是只报一个总数；
     · bench-record / bench-check：把 `go test -bench` 的输出记成基线（存 JSON），
       下次跑完与基线比对，变慢超过 20% 记回归、变快记改进、新用例记 new。
   容差 20% 是为了避开机器噪声，避免每次跑都一堆假警报。
   基线文件放在数据目录，跨会话可复用，升级不丢。

6. 结构化数据查询（datatable 工具）
   CSV / JSON 不再整表塞进上下文让模型自己数。工具侧提供 info（列名与行数）、
   head、select（挑列）、filter（按列与运算符过滤）、sum（求和）、group（分组计数）。
   为什么放工具里：一万行 CSV 灌进上下文既贵又算不准，交给程序算，模型只拿结果。
   全角逗号、带引号字段、空值这些常见脏数据在解析层消化掉，不让模型去猜。

----------------------------------------------------------------
三、P2 —— 图片理解、约定沉淀、任务侧栏
----------------------------------------------------------------

7. 图片理解（read_image 工具）
   给本地图片路径就能读：识别格式、解析宽高、把图片编码成多模态载荷随消息发出，
   模型看到的是真图，不是文件名猜内容。
   约束：只认常见图片格式（png/jpg/jpeg/gif/bmp/webp），非图片文件明确拒绝并列出支持格式；
   单张超过 8MB 只返回元信息、不发送图片，避免把内存和上下文一起打爆；
   带图消息最多 4 张，超出按顺序截断并在结果里说明。

8. 项目约定自动沉淀（AGENTS.md）
   过去：/init 生成骨架，之后靠人维护，很快过期。
   现在：轮末自动检测项目类型（Go / Node / Python 等，按文件特征判断），
   把构建、测试、目录要点写进 AGENTS.md 的自动区块。
   幂等：用标记块包裹，重复写入只更新块内内容，用户手写的部分一律不碰；
   项目类型没变化时内容不变，不会每次生成一堆无意义 diff。

9. 任务侧栏
   右侧常驻一块状态面板：进行中的目标与进度（如 3/5）、待办清单（完成/进行中/待办）、
   运行中的子任务数量。数据来自 todo_write 与执行引擎的实时事件，
   长任务不用翻聊天记录找"现在到哪了"。
   无任务时整块收起，不占版面。

四、自检与验证
----------------------------------------------------------------

自检用例从 38 项扩到 44 项，新增 6 项同样走真实数据主路径：
  ST39 目标收敛循环        验证失败回炉再来一轮后达成；无进展 2 轮触发停滞；空计划拒绝
  ST40 Git 提交与回滚闭环  真建仓库、真提交两次、回滚 1 步内容还原；非仓库被拦
  ST41 并行写隔离合并      3 个改动合入、1 处冲突另存 .from-*、首个胜出规则
  ST42 覆盖率与性能基线    真解析 coverprofile 6/9 语句与两个 benchmark，识别提速
  ST43 结构化数据查询      真实 CSV 上跑 info / filter / sum / group，校验合计 450
  ST44 图片理解与任务侧栏  真读 PNG 得尺寸与载荷、非图片被拒；侧栏待办与子任务计数
结果：44 项，通过 41、失败 0、跳过 3（无 git 环境跳过 ST40，需联网/模型的检查在离线环境跳过）。

编译与单测：
  · linux 侧 go test 覆盖 core / agent / tools / codeidx / llm / selftest 六个包，全通过；
  · GOOS=windows GOARCH=386 与 amd64 双架构 go build ./... 全通过；
  · build.sh 双架构编译 + rsrc 嵌图标 + PE 资源校验 + ZIP 打包。

----------------------------------------------------------------
五、升级说明
----------------------------------------------------------------

· 直接用新 exe 覆盖旧的即可，%APPDATA%\Win7Harness 下的会话与配置无需迁移；
· 新增配置项（目标轮数上限、覆盖率阈值、性能容差）全部有默认值，
  零值等于"用默认"，不改变 v1.24 的既有行为；
· 未安装 git 的机器：/commit、/rewind 会明确说明不可用并退回文件快照，
  其余功能不受影响；装了 git 但目录不是仓库时同样给出明确提示，不会静默失败；
· AGENTS.md 的自动区块用标记包裹，不想让它自动维护，删掉该区块后把
  项目类型标记一并移除即可停止更新，手写内容始终保留。
