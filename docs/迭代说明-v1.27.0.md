WIN7 Harness v1.27.0 迭代说明
================================================================

版本定位：把"只能坐在电脑前盯着"变成"人走了活还在跑"。
三个方向：
  P0 人不在也能指挥——手机远程指挥台、定时任务、目录守护；
  P1 长期跑得下去——更新检查、大仓库索引冷启动不再每次重建；
  P2 看得清、看得广——两个会话并列对照、高对比主题与字号缩放。

适用环境不变：Windows 7 SP1 + KB2533623 + KB4474419，单文件 exe，零运行库依赖，
不装 .NET、不装 VC++、不写注册表。
包名：WIN7Harness-v1.27.0-win7.zip（内含 x86 / x64 双架构 exe、README、setup.bat）。

----------------------------------------------------------------
一、P0-1 手机远程指挥台（/remote）
----------------------------------------------------------------

过去：代码跑在 Win7 老机或远端机器上，人一离开键盘就只能等；想看一眼进度得回座位。
现在：程序内置一个 HTTP 服务，手机浏览器打开就能看状态、发指令，不装 App、不走第三方。

  · 开关与范围
      /remote on     开启，默认只监听局域网（0.0.0.0:8765）
      /remote local  只监听 127.0.0.1，本机浏览器预览
      /remote off    立即停止监听
      默认关闭：不加参数启动时一次监听都不开，端口不会被无声占用。

  · 鉴权链路
      配对码 6 位、5 分钟有效、用一次即作废（PairCode() 生成，配对成功后立刻换新）；
      手机 POST /api/pair 带 code 换随机 token，之后所有接口都要
      Authorization: Bearer <token>，缺 token 一律 401；
      错误配对码同样 401，不给"码错了还是过期了"的区分，避免被枚举试探。

  · 能做什么、不能做什么
      能：GET /api/status 看版本、模型、工作目录、当前任务；
          POST /api/send 发文本指令，指令进主界面执行队列（Pending 计数可见）。
      不能：手机上点不了"同意"。高危操作（删文件、跑命令）仍然回到电脑端确认，
            手机端状态里显示"等待电脑确认"。
      不做公网穿透、不内置中转服务器：外网访问请自行做端口映射，
      并先确保 VPN / 密码到位，暴露到公网的风险由使用者承担。

  · 为什么不用 WebView2
      Win7 上装不了 WebView2，且本项目的底线是零运行库依赖。
      所以手机端页面是一张自绘的移动端 HTML（内联样式，无外链、无 CDN），
      电脑端只用 net/http 收发 JSON，不加任何第三方框架。

  · 端口占用怎么办
      配置项 remote_port 改端口；启动失败会在界面里直接说"端口被占用"，
      不会静默降级成随机端口让你找不到。

二、P0-2 定时任务（/loop）
----------------------------------------------------------------

过去：想让"每天早上汇总昨天的提交"自动跑，只能去 Windows 任务计划里配，
      还得自己拼命令行、自己管工作目录，出错了没人告诉你。
现在：一句话登记，到点自己开新会话跑。

  · 排期写法（都能用）
      30m / 2h / 1d        固定间隔
      every 30m            同上，every 前缀会被剥掉
      daily 09:30          每天固定时刻，已过的时刻自动顺延到明天
      每天 09:30           中文别名
      weekly mon 09:00     每周固定日（mon..sun / 周一..周日都认）

  · 约束
      最小间隔 30 秒：再密只会烧 token 和 CPU，低于此值直接拒绝并说明原因；
      排期表达式解析失败、提示词为空、工作目录不存在，都在登记时报错，不留到执行时才炸。

  · 运行方式
      主循环 5 秒一拍检查到期项；到点启动一个新会话执行，不打断当前对话；
      执行后 MarkRun 推进下一次触发时间，同一条任务不会被重复触发；
      结果留在会话列表里，可回看、可导出。

  · 管理
      /loop list        清单：序号、排期、下次触发时间、开关状态、提示词摘要
      /loop off 1       暂停（保留配置）
      /loop del 1       删除
      清单与下次触发时间落盘到配置目录，重启后继续按原计划走。

三、P0-3 目录守护（/watch）
----------------------------------------------------------------

过去：改完文件要自己想起来"该跑测试了"。
现在：盯住目录，真有改动就触发。

  · 判定口径
      首次 Poll 只建基线，不触发——否则第一次就报"全部新增"，等于没做差异；
      之后比较 新增 / 修改 / 删除 三类变化，任一非空才触发；
      同一状态连续 Poll 不重复触发（快照即状态，无变化就是无变化）。

  · 过滤
      匹配：默认不限后缀（任何文件变动都算），可用 --glob 收窄到具体后缀，
            支持逗号分隔与通配符：/watch add D:\proj --glob *.go,*.md 改动后跑测试；
            不写 --glob 时建议配合 --ignore，否则日志、临时文件会把规则刷爆；
      忽略：.git / .svn / .hg / node_modules / vendor / dist / build /
            __pycache__ / .idea / .vscode / .cache / target / bin / obj，
            以及规则里额外指定的目录。
      被忽略的文件不进快照，因此它的增删也不会被误报成"删除"。

  · 重启安全
      快照随规则一起落盘。没有这一步，重启后第一次比较会把整个仓库判成
      "全部新增"，然后立刻触发一次假执行——这是最容易踩的坑，所以单独验证。

  · 管理
      /watch list 看规则、匹配模式、上次触发时间；
      /watch del 1 删除。

四、P1-1 更新检查（/update）
----------------------------------------------------------------

  · 只在你要它查的时候查
      默认不联网、不带任何内置清单地址。配置 update_url 指向清单 JSON 后，
      /update 看上次结果，/update check 立即查一次；
      配置 check_update_on_start 可让启动时静默查一次（只提示，不自动下载替换）。

  · 清单格式（自己托管一份即可）
      {
        "version": "1.27.1",
        "notes": "修复若干问题",
        "files": {
          "amd64": {"url": "https://.../WIN7Harness-amd64.exe", "sha256": "…", "size": 123},
          "386":   {"url": "https://.../WIN7Harness-386.exe",   "sha256": "…", "size": 123}
        }
      }

  · 校验
      版本比较按数字段比，不会出现 "1.9.9 > 1.27.0" 这种字符串比较错误；
      按运行时架构（386 / amd64）挑包，没有对应架构就明确说"没有你的架构"；
      下载后校验 SHA256，不符直接丢弃并删临时文件；体积过小（<1KB）也判为
      "下错文件"而不是拿去覆盖——宁可不更新，也不能把正在用的 exe 换成半截。

五、P1-2 大仓库索引冷启动
----------------------------------------------------------------

过去：每次启动都把整个仓库重扫一遍，几万文件的仓库要等十几秒，老机器更久。
现在：索引压缩落盘 + 指纹校验。

  · 落盘位置：配置目录下 codeindex.json，gzip 压缩（带 gzip 魔数，肉眼可验）；
  · 指纹两项：CacheSchema（结构版本）与 RulesVersion（忽略规则版本）；
  · 命中条件：两者都一致才复用，任一不符就重建——结构变了还硬用旧缓存，
    比慢更糟（符号表错位会让 code_search 给出错误的文件行号）；
  · 失效时机：/index 强制重建，/index inc 增量刷新改动过的文件。

  自检里用真实仓库验证：压缩后必须比原始 JSON 小，且把 Schema / Rules 改一位后
  必须判为不可用。

六、P2-1 多会话并列（/compare）
----------------------------------------------------------------

  · /compare 列出可对照的会话；/compare 3 把第 3 个放到右栏，当前会话在左栏；
  · 左右两栏独立滚动、各自高亮，长行按栏宽折行，不串行、不挤压；
  · 用途：同一问题两个方案的输出对照、改前改后对照、两个分支的实现对照；
  · Esc 返回，不影响两侧会话本身。

----------------------------------------------------------------
七、P2-2 高对比主题与字号缩放
----------------------------------------------------------------

  · /theme hc 高对比：纯黑底、纯白字、亮黄强调，边框加粗——老 TN 屏、
    投影、远程桌面压缩后仍然看得清；/theme dark|light 切回原主题；
  · /font 80~200：只放大对话内容（含代码块），工具栏与按钮保持原尺寸，
    避免文字顶出行框；越界值（240、40）在配置归一化时夹回 100，
    不会出现"字号 0 导致整屏空白"这种自伤；
  · 两者都持久化到配置，下次启动沿用。

八、自检：60 项，新增 6 项
----------------------------------------------------------------

新增用例全部用真实资源验证，不接受"编译通过就算过"：

  ST55 定时任务排期与落盘   真实解析 every/daily、10s 被拒、落盘往返 2 条、到期 1 条
  ST56 目录守护变化检出     真实临时目录：改 1 个、加 1 个、删 1 个不匹配文件，
                            验证触发项正确、忽略规则生效、无变化不重复触发、快照落盘
  ST57 手机指挥台鉴权       真实监听 127.0.0.1 随机端口：错码 401、无 token 401、
                            正确码换 token、指令进队列、空指令 400
  ST58 更新检查与包校验     httptest 起真实清单与包：识别 9.9.9、同版本不误报、
                            坏 JSON 报错、架构匹配、SHA256 不符被拦截
  ST59 索引缓存指纹校验     真实目录 120 个符号：gzip 魔数、压缩后更小、
                            Schema/Rules 改一位即失效
  ST60 字号缩放与主题边界   hc 保留、240/40 夹回 100、130 保持、非法主题回落

首轮结果：60 项通过 54、失败 3、跳过 3。三处失败全部是真实缺陷，已修：

  1) ST55 "every 30m" 解析失败——剥离 every 前缀只用于分支判断，
     真正解析时长时又把原文喂了进去，"every" 被当成数字。
     修：default 分支改用剥离后的 low。
  2) ST57 配对码请求返回 400 "只接受 POST"——用例拿 Start() 返回的
     展示地址（http://…/）去拼请求，拼成 http://http://…，被客户端当成
     重定向后 POST 降级成 GET。修：用 srv.Addr() 取真实监听地址再拼 base。
  3) ST58 下载校验失败——测试载荷 21 字节，被实现的最小体积阈值（1KB）
     判为"不是可执行文件"。这是实现的保护在正常工作，改用 4KB 载荷。

修复后：60 项通过 57、失败 0、跳过 3，通过率 100%（跳过不计入）。

跳过 3 项与原因（不粉饰）：
  · ST40 Git 提交与回滚闭环：云端环境没有 git，只能在装有 git 的 Win7 上重跑；
  · v1.24 的 web_fetch TLS 抓取真机验证：依赖 Win7 系统根证书与 schannel 行为，
    云端 Linux 跑通不代表 Win7 跑通；
  · v1.24 的低内存实机反馈：需在 256MB 档下观察真实界面的内存占用与降级表现。
  这三项建议装机后各手工确认一次，确认前不要当成已验证。

九、升级与兼容
----------------------------------------------------------------

  · 版本号 1.27.0，配置向后兼容：新增项均有默认值，
    旧配置文件（v1.26 及更早）直接可用，不需要删配置重来；
  · 新增配置项：remote_enabled / remote_lan / remote_port /
    update_url / check_update_on_start / font_scale，均为可选；
  · 覆盖升级：setup.bat 装过的运行新版安装包；绿色版直接替换 exe。
    会话、配置、索引缓存都在 %APPDATA%\Win7Harness，不会被覆盖；
  · 若要清干净：删 %APPDATA%\Win7Harness（会丢会话历史，谨慎）。
