WIN7 Harness v1.24.0 迭代说明
================================================================

版本定位：把"只在当前对话里聪明"补成"能上网查、能翻旧账、报错说得准、花钱花得省"。
v1.23 解决了"改完能自己验"，这一版接着解决三件更基础的事：
信息来源够不够（联网 + 历史）、报错定位准不准（结构化诊断）、
成本能不能压下来（模型路由 + 子代理预算），外加把长任务刷屏的工具卡收起来。

适用环境不变：Windows 7 SP1 + KB2533623 + KB4474419，单文件 exe，零运行库依赖，
不装 .NET、不装 VC++、不写注册表。
包名：WIN7Harness-v1.24.0-win7.zip（内含 x86 / x64 双架构 exe、README、setup.bat）。

----------------------------------------------------------------
一、P0 —— 信息来源与报错定位
----------------------------------------------------------------

1. 联网搜索（web_search 工具）
   过去：模型的知识停在训练截止日，"最新版本"、"现在官网地址"这类问题只能靠猜。
   现在：内置网页检索工具，按 duckduckgo → duckduckgo-lite → bing 依次尝试，
   解析标题/链接/摘要三个字段返回给模型。
   工程细节：
     · 搜索结果链接多是 //duckduckgo.com/l/?uddg=<编码后的真实地址> 这种跳转壳，
       解析时还原成真实 URL，否则模型点不开、引用也错；
     · 单页响应设上限，防止某个引擎返回超大页面把内存吃掉；
     · 三个引擎全部失败时明确返回"未查到"，不编造链接——宁可说不知道；
     · 命中登录墙/人机验证不在工具里硬闯，交回给用户手动处理。

2. 跨会话回忆（/recall + history_search 工具）
   过去：用户问"上周那个方案你之前是怎么说的"，只有当前会话在上下文里，答不上来。
   现在：扫本地会话文件（含 gzip 压缩档），按内容时间从新到旧，命中处给上下文片段，
   并标注这句话是"你"说的还是"它"答的，可直接 /open 序号跳过去看全文。
   关键取舍：
     · 时间窗按"会话内容时间"判定，不按文件修改时间——老会话被拷贝/备份过之后
       mtime 是新的，用 mtime 会把 40 天前的对话当成本周内容；
     · 多个关键词必须同时出现（AND），不是任一命中就返回，避免搜"内存 脚本"
       把两个不相干的会话一起端上来；
     · 单会话解压上限 64MB、单次最多扫 80 个会话，几千个会话的库不会卡住界面。

3. 构建报错结构化（ParseDiagnostics）
   过去：验证失败后把整段编译输出灌回模型，几万字的日志里可能只有三行有用。
   现在：Go / TypeScript / ESLint / Rust / Python 五套规则抽成
   "文件:行:列 + 原因"，同一条报错去重，最多取 12 条。
   额外补了 Python traceback 的 File "x.py", line N 形态——粘 pytest 回溯时
   直接指到炸掉的那一行，不用模型自己数行号。
   反向保护：正常输出（PASS / all tests passed）不会被误判为错误，
   否则"测试全过"会被报成失败，模型就开始改本来没坏的代码。

----------------------------------------------------------------
二、P1 —— 成本：子代理预算与模型路由
----------------------------------------------------------------

4. 子代理结论预算
   过去：只读子代理（读文件、检索代码）把整个文件内容回灌主对话，一次就能顶满上下文。
   现在：子代理结论按字数预算裁剪，留头（结论要点）留尾（没做完的部分），
   中间标注"省略 N 字，需要细节请指派更具体的子任务，或让它写入文件后由主对话读"。
   预算默认 6000 字，可配；配 0 视为使用默认值，不会把结论吃成空。

5. 模型路由（/model router on|off，/model fast）
   过去：压缩上下文、只读检索这类"读得多想得少"的活也走最贵的模型。
   现在：可指定一个快速模型专门跑上下文压缩与只读子代理，主对话与写文件子代理
   仍走主模型。
   保守设计：
     · 默认关闭，必须显式 /model router on 才分流；
     · 快速模型未配置或与主模型同名时自动回落主模型，并在 /model 状态里明说；
     · 两个模型的 token 分开记账，成本看板按各自单价算，不会把两笔账混成一个假数。

----------------------------------------------------------------
三、P2 —— 界面：命令面板与工具卡折叠
----------------------------------------------------------------

6. 命令面板补齐
   /recall、/tools、/model 等新命令全部进面板，前缀匹配排在最前，
   敲 "/to" 就能第一眼看到 /tools。

7. 工具卡分组折叠
   过去：一条消息里跑了七八个工具，卡片一路往下铺，用户要翻很久才看到结论。
   现在：连续 3 条以上"已结束"的工具卡收成一行摘要——执行步数 · 失败数 · 总耗时，
   点这一行就地展开、再点收起。
   硬约束：还没跑完的工具一定逐条可见。用户要的是"现在卡在哪一步"，
   把运行中的卡藏起来等于把进度条藏起来。
   开关：Ctrl+Shift+T 全局切换，/tools fold、/tools off 亦可；
   折叠状态按会话 + 消息 + 组起点记忆，切会话不会串味。

----------------------------------------------------------------
四、自检与验证
----------------------------------------------------------------

自检用例从 32 项扩到 38 项，新增 6 项都走真实数据主路径：
  ST33 联网搜索结果解析    跳转壳剥离、摘要抽取、上限截断、无结果不编造
  ST34 跨会话历史检索      真落盘两个会话，验多词 AND、时间窗、角色标注
  ST35 构建报错结构化      Go / TS / Python 三态定位，正常输出不误报
  ST36 子代理结论预算      超长文本裁剪后留头留尾带省略提示
  ST37 模型路由与分账      四种路由状态 + 主/快速账本无污染
  ST38 工具卡分组折叠      折叠边界、运行中拦截、展开回退
结果：38 项，通过 36、失败 0、跳过 2（需联网的连通性检查在无网环境自动跳过）。

编译与单测：
  · linux 侧 go test 覆盖 core / agent / tools / codeidx / llm 五个包，全通过；
  · GOOS=windows GOARCH=386 与 amd64 双架构 go build ./... 全通过；
  · build.sh 双架构编译 + rsrc 嵌图标 + PE 资源校验（RT_ICON=9、图标组 9 档）+ ZIP 打包。
  · 注：win32/ui 包有若干 unsafe.Pointer 的 vet 提示，是 Win32 系统调用的既有形态，
    v1.23 之前即存在，不影响构建与运行。

----------------------------------------------------------------
五、升级说明
----------------------------------------------------------------

· 直接用新 exe 覆盖旧的即可，%APPDATA%\Win7Harness 下的会话与配置无需迁移；
· 配置结构向后兼容：新增字段（模型路由开关、快速模型、折叠开关）全部是可选字段，
  默认零值等于"保持 v1.23 的行为"——不主动开路由、不主动改预算；
· 想回到 v1.23 的老界面行为：/tools off 关折叠、/model router off 关路由即可，
  不必回滚版本。
