# 功能对比与迭代规划（v1.1.0）

> 目标：以市面主流 coding harness 的能力基线为参照，定位 WIN7 Harness 的差距，并把差距拆成可落地、可验证的迭代批次。
> 约束：Win7 SP1 可用、Go 1.20.14、CGO 关闭、单文件 EXE、零运行库依赖。凡与约束冲突的能力，一律归入"不做"并说明原因。

---

## 一、市面 harness 的能力全景

把各家功能归到 8 个能力域，避免逐产品罗列造成噪音。代表产品：Claude Code、Codex CLI、Aider、Cline、OpenCode。

| 能力域 | 具体能力 | 行业现状 |
|---|---|---|
| 上下文工程 | 项目规则文件、自动压缩、会话恢复、文件引用 @、语义检索 | 已成标配。Claude Code 用 CLAUDE.md，Codex 用 AGENTS.md 链式向上查找；长会话靠 auto-compact；Aider 用 repo map 做结构索引 |
| 工具与权限 | 差分审批、沙箱分档、并行工具调用、可回滚 | Codex 的核心范式是"沙箱内直接干，越界才问"，沙箱三档（只读 / 工作区可写 / 全权限）与审批策略正交；编辑类操作普遍有 checkpoint |
| 任务编排 | 计划模式、待办清单、子 agent、多 agent 协作 | Claude Code 有 plan mode、Task、subagent 与 agent teams；Cline 用 plan/act 两段式 |
| 扩展机制 | MCP 客户端、hooks、自定义命令、技能包 | MCP 已是事实标准；hooks 在文件保存/命令执行前后挂钩子；slash command 用来固化常用流程 |
| 代码库理解 | 结构索引、符号跳转、增量检索 | Aider 的 repo map 用 tree-sitter 抽符号做压缩地图，是长上下文里最省 token 的方案 |
| 版本控制 | 自动提交、diff 摘要、按改动回退 | Aider 默认每轮改动自动 commit，回退粒度是提交 |
| 交互与呈现 | 流式、工具轨迹、diff 高亮、图片输入 | TUI/Web 双形态；终端产品普遍支持粘贴截图 |
| 工程化 | 非交互模式、CI 集成、成本统计、遥测 | `codex exec`、headless 调用、token/费用统计 |

## 四、明确不做

| 能力 | 不做原因 |
|---|---|
| Electron / WebView2 界面 | Win7 无 WebView2（官方最低 Win10），装不上。现有自绘 GDI 是唯一解 |
| 云端沙箱执行 | 与"本地优先、代码不出机"的定位冲突 |
| 依赖 WSL2 的能力 | Win7 无 WSL2 |
| .NET / Python 插件运行时 | 破坏零依赖开箱即用 |
| tree-sitter 符号索引 | 需 CGO 或预编译二进制，与 `CGO_ENABLED=0` 冲突，改用轻量正则索引替代 |

## 五、下一轮迭代计划

### P0（v1.2，决定"能不能长时间干活"）

| 能力 | 价值 | 做法 | 风险 |
|---|---|---|---|
| 计划模式 | 动手前先出方案，避免大范围误改 | 新增只读阶段：工具集裁到读取类，输出计划后等用户点"执行" | 中，需改 engine 状态机 |
| 编辑前 diff 预览 | 用户改前就能拦住错误改动 | 复用快照：写盘前对旧内容做 unified diff，弹确认（可设置"本会话内不再问"） | 中，UI 需评审 diff 卡片 |
| git 集成 | 回退粒度从"单文件"升到"一次任务" | 检测是否 git 仓库，前后 `status --porcelain` 对比；`/commit` 生成中文提交信息 | 低 |
| @ 文件引用补全 | 少打字，指向更准 | 输入 `@` 弹文件列表（复用 glob），选中插入路径 | 中，纯 UI |

## 六、判断依据

- 优先级排序按"任务完成率影响 × Win7 约束下的可行性"，不按产品热度。
- 权限模型走 Codex 的差分路线（默认放开、越界才问），而不是每步都确认——后者在长任务里会被用户无脑点"是"，等于没有防护。
- 上下文策略先做"摘要压缩 + 快照回滚"，再做"索引检索"：前者防止信息丢失，后者只是省 token，前者优先级更高。
