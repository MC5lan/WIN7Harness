# 性能与稳定性审计（v1.31.1）

> 审计对象：`D:\win7harness\work\win7harness`（v1.30.0 源码 + 工作区未提交的 v1.31 交互改动）
> 触发问题：后台进程/界面随机卡死；鼠标滚轮在各功能页卡顿或完全不动；整体观感像未完工。
> 审计方式：静态阅读 + 真实 Win32 消息驱动 + UI 帧成本探针 + goroutine 栈转储 + 多次快速启动/退出压力测试。

---

## 一、结论摘要

| 类别 | 结论 |
|---|---|
| 卡死根因 | **窗口线程没有 `runtime.LockOSThread`**。Win32 窗口/消息队列属于创建它的 OS 线程，Go 调度器把主 goroutine 迁移到别的线程后，`ShowWindow`/`SetWindowPos`/`WM_TIMER` 会等一条永远不会处理消息的线程，表现为随机启动卡死、窗口不出现、界面无响应。 |
| 滚轮根因 | 窗口层先把滚轮增量 `delta/120`，kit 页再乘 `4/120` 取整 → **标准滚轮一格变成 0，页面完全不动**；聊天/设置/侧栏的滚动方向符号也被写反。 |
| 卡顿根因 | 绘制线程里存在同步 I/O：Git 身份子进程（设置页每帧）、工作区 `WalkDir` + `git` 子进程（总览页每帧）、会话索引同步解析（会话中心首帧）、技能/记忆/崩溃/网卡快照（每 500ms）、@ 文件补全遍历（首次输入）、会话 JSON+gzip+备份写盘（流式每 400ms）。 |
| 后台任务根因 | 后台命令的 stdout 是 writer，`os/exec` 会等管道 EOF；孙进程继承写端时 `cmd.Wait()` 永不返回，任务永远“运行中”。已加 `WaitDelay`。 |
| 观感问题 | kit 页无滚动条、设置页必须滚到底才能保存、工作区页没有“本会话改了什么”、诊断页空“建议：”行、用量页卡片只占左上角、底部状态栏与内容穿透。 |
| 修复后验证 | `go build ./...` ✅、`go test ./...` 全绿 ✅、自检 76/77（1 SKIP）✅、快速启动/退出 15/15 窗口可见 ✅、滚轮/会话/设置/工作区实机截图 ✅。 |

## 二、P0：卡死与不可用

### P0-1 窗口线程未锁定（随机启动卡死）

**证据**

- `internal/ui/window.go` 的 `RunWindow` 在 `CreateWindow` 后进入 `GetMessage`，但从未调用 `runtime.LockOSThread()`。
- 压力测试中 UI 看门狗抓到的主线程栈：
  - `win32.ShowWindow` → `user32` 内部等待 30s+；
  - 后续复现为 `win32.SetWindowPos` → `user32` 内部等待；
  - 另一次为 `GetMessage` 等待，但 Timer 永不到达。
- 同一台机器上，挂起时进程 CPU 不增长、所有线程处于等待；外部 PowerShell 对同一 HWND 调用 `SetWindowPos(SWP_SHOWWINDOW)` 却能立即显示，说明不是窗口/图标/绘制本身的问题，而是**消息队列线程归属错位**。

**修复**

- `RunWindow` 开头调用 `runtime.LockOSThread()`，窗口创建、消息循环、窗口过程回调、低级键盘钩子全部固定在同一 OS 线程。
- 节拍从 `SetTimer`/跨线程 `PostMessage` 改为 `PeekMessage + 进程内 30ms 节拍`：
  - 不再依赖“WM_TIMER 一定到达”；
  - 不会出现后台 goroutine 在消息队列锁上与 UI 线程互等；
  - 空闲 CPU 实测约 1.2% 单核（5 秒 0.062s），可接受。
- 窗口显示用同步 `SetWindowPos + SWP_SHOWWINDOW`，首个节拍再补一次前台/首帧；失败会重试并写日志。
- 新增 UI 看门狗：3 秒无心跳即转储全部 goroutine 栈到 `crash/ui-stall-*.txt`，通知中心/诊断页可见。

**验证**

- 连续 15 次“启动 → 等窗口出现 → 强杀 → 0.5~0.7 秒后重启”压力测试：15/15 窗口可见，0 次 UI 卡顿报告。
- 正常 5 秒间隔启动 5/5、10/10 通过。

### P0-2 滚轮在 kit 页完全失效 / 方向错误

**证据**

- `internal/ui/window.go`：`delta/120` 后把 ±120 变成 ±1。
- `internal/app/app.go` 旧 kit 分支：`line := int32(-delta) * 4 / 120`。`±1 * 4 / 120 = 0`，所以会话中心、扩展、自动化、用量、诊断、通知页滚轮完全不动。
- 聊天/设置/侧栏旧代码：`scroll -= delta * 64`，在 `delta` 已为负时方向正确；改成整格后需要同步改符号，否则滚轮只能“顶到 0”。

**修复**

- 窗口层只传原始增量（可为 40/80/120），不再取整。
- `App.wheelNotches` 做小数累积：40×3 凑成一格，240 一次两格，高精度滚轮/触控板不再丢事件。
- 所有滚动目标统一用“整格 × 像素/行”：
  - kit 页：`ScrollBy(step*64)`；
  - 聊天/设置/诊断：`+= step*64`；
  - 侧栏：`+= step*56`；
  - 输入框：整行。
- kit 页 `ScrollBy` 在写入时就夹到 `ScrollMax`，不再出现“滚到底后先滚回欠账”。
- 新增 `ScrollPage / ScrollHome / ScrollEnd`，PageUp/PageDown/Home/End 在所有 kit 页可用。
- 新增右侧滚动条（7px 圆角轨道 + 滑块），长列表终于有位置反馈。

### P0-3 绘制线程里的同步 I/O

已定位并移除的每帧/高频阻塞点：

| 位置 | 旧行为 | 新行为 |
|---|---|---|
| 设置页 Git 身份 | 每帧 `git config user.name/email` 两次子进程 | 后台 pageData 30 秒刷新一次 |
| 工作区总览 | 每帧 `filepath.WalkDir`（首次）+ `git rev-parse` + `git diff` | 后台扫描，页面读快照；支持“重新扫描” |
| 会话中心 | 首帧同步 `SessionIndex` 解析全部会话文件 | 后台索引 + 启动预热 + 15 秒 TTL |
| 扩展页计数 | 每 500ms 同步 `skills.Scan` / `LoadAgentDefs` / `LoadMemory` / `ListCrashReports` / `net.Interfaces` | pageData 后台快照，绘制只读 |
| 通知/诊断崩溃列表 | 每帧 `os.Stat` 每份报告 | 后台一次 stat，缓存大小/时间 |
| @ 文件补全 | 首次输入遍历工作区 | 后台预热 60 秒 TTL，扫描完成自动刷新候选 |
| 消息内文件路径 | 每个可见路径每帧 `os.Stat` | 3 秒路径缓存，点击时仍实时校验 |
| 设置页代理提示 | 每 3 秒读 WinINET 注册表 | 后台 pageData 10 秒刷新 |

### P0-4 会话落盘占用 UI 线程

**证据**

- `saveConv` 在流式 `content` 事件里每 400ms 调用一次；`persistConv` 在主线程做 `json.Marshal + gzip + 读取旧文件备份 + 写盘`。长会话几 MB 时会出现周期性 100ms+ 卡顿。

**修复**

- 新增 `convSaveQueue`：UI 线程只做深拷贝快照（`snapshotConv`），后台单线程按会话 ID 合并写出。
- 同一会话连续保存只写最新一份；不同会话按入队顺序写。
- 退出时 `stop + flush(8s)`，确保最后一轮输出落盘。
- 删除会话前先 `flush`，避免排队中的旧快照把已删除的会话写回来。

### P0-5 后台任务 `Wait` 永不返回

**证据**

- `internal/tools/bgtask_windows.go` 用 `sinkWriter` 接收 stdout/stderr，`os/exec` 会起内部 goroutine 拷贝管道；当 `cmd.exe` 派生的孙进程继承写端时，`cmd.Wait()` 等不到 EOF，`doneCh` 不关闭，任务状态永远“运行中”。

**修复**

- `cmd.WaitDelay = 3s`：进程退出后最多再等 3 秒收管道。
- 新增“自动化 → 后台任务”页：运行中/已结束、命令、启动/结束时间、输出大小、备注、一键终止；终止动作异步执行，不阻塞界面。

## 三、P1：正确性与体验

### P1-1 kit 裁剪栈未恢复导致整页空白

- `kit.Ctx.PushClip` 把“上一个裁剪矩形”压栈，但当时没有记录“上一个是否真的有裁剪”；`PopClip` 在栈非空时把 `clipSet` 留成 `true`，下一帧所有元素都被 `Visible()` 判为不可见，会话中心整页只画背景和顶栏。
- 修复：`clipFrame{r Rect; set bool}` 成对保存/恢复；`BeginFrame` 强制清空裁剪状态。

### P1-2 会话中心首屏空白 / 无加载提示

- 索引改为异步后，首帧可能还没有数据。页面现在显示“正在读取会话…”并标（刷新中），后台完成后自动重绘。
- 打开会话文件也改为后台读，避免几十 MB 长会话点开即冻。

### P1-3 工作区扫描的并发代际

- 用户连续点“重新扫描”或切换目录时，旧扫描可能后完成并覆盖新结果。
- 修复：`wsState.gen` 代际号；只有 `dir` 与 `gen` 都匹配才写回。

### P1-4 工作区“本会话改动”每帧解析

- 新增列表后，如果每帧扫描全部工具卡 JSON，会重新引入卡顿。
- 修复：按 `App.ver` + 工作目录缓存；只有消息变化才重建。

### P1-5 内容穿透底部状态栏

- 设置页底部状态栏没有底色，滚到一半的“保存设置”按钮会从状态文字后透出来。
- 修复：状态栏区域铺底色 + 顶部细线，内容裁剪到状态栏之上。

### P1-6 页签/卡片视觉

- 诊断页对所有检查项都画“建议：”，没有建议时留下空行 → 只在 `Hint != ""` 时显示。
- 用量/成本页三张分项卡只占左上角 → 用 `kit.Expanded` 均分整行。
- 设置页必须滚到底才能保存 → 顶栏新增“保存设置”。

## 七、v1.31.1 追加（继续优化）

- **聊天页视口虚拟化**：`laySeg` 增加消息段绝对 `y`，`laySegs` 不再每帧摊平成 `a.items`；绘制时用二分找到首个可见段，只遍历可见段。1200 条消息（2400 条 msg）实机：窗口 386ms 出现，滚动时应用层 Paint 平均 1.5ms，不再随消息数线性复制可视项。
- **`/open` 跳转修正**：`msgTopOffset` 直接返回段 `y`，不再累加硬编码的 14px 间距（旧代码在 dense 模式 14px、普通 20px 下会跳偏）。
- **会话中心悬停操作**：行悬停出现「置顶 / 删除」；置顶按稳定 ID 写回会话文件，删除走确认框并按 ID 删除，避免确认期间列表重排误删别的会话。
- **兼容渲染（GDI）开关**：设置 → 行为新增。老显卡/16bpp/远程桌面下可切 GDI（实测 1200 条消息滚动 Paint 平均 7ms，矢量约 18ms 总成本），重启生效；`WIN7H_RENDER` 仍可覆盖配置。
- **会话启动懒加载**：`loadAllConvs` 改为先用 `SessionIndex` 流式拿标题/条数/预览，只同步读当前会话；其余空壳后台补全最近 24 条，更老的等点开再读。会话中心列表上限从 60 提到 2000，不再把 91 个会话显示成 60 条。`/find` 发现未载入正文时会提示并后台补全，第一次结果不是全量。
- **置顶/改名安全**：空壳会话点置顶/改名会先后台载入正文再落盘，避免把只有索引的壳写回磁盘；删除确认按稳定 ID 执行。

> 注：GDI 模式不再有矢量抗锯齿，视觉更“硬”；默认仍为 canvas。

- **会话索引缓存**：`sessions/.sessions-index.json`，按目录项 mtime+size 复用摘要；91 个会话实测冷启动 283ms → 热启动 121ms，1200 条消息单会话 274ms → 167ms。
- **设置页左侧分组导航**：模型/权限/网络/行为/预算/钩子/Git 七组直达；内容区右侧给滚动条留 18px，修复滚动条压卡片描边。
- **高 DPI 响应式**：模型行、Git 身份行在窄宽度自动拆成两行；`WM_GETMINMAXINFO` 把最小窗口夹到当前屏幕工作区，避免 150% 下窗口被撑出屏幕。
- **DPI 验收开关**：`WIN7H_FORCE_DPI=1.25|1.5` 不修改系统缩放即可复现高 DPI 布局。
- **UI 自动回归**：`scripts/ui_regression.ps1`，驱动真实 Win32 消息验证页面切换、滚轮、长会话、懒加载、kit 返回按钮、无卡顿/无 panic、干净退出；1.0/1.25/1.5 三档各 15/15 通过。
