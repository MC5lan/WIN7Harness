# WIN7 Harness v1.17.0 迭代说明：抽屉式面板与自适应

## 一、这一版解决什么

v1.16 的侧栏/检查器只会"折叠"，宽度是写死的 232 / 272。窗口一小，两个面板一起打开就把会话区压成一条缝。
用户提的诉求是：**侧栏做成抽屉式、可伸缩，其他 UI 交互层同样处理，并且要自适应**。

v1.17 把两侧面板从"固定占位的分栏"改成"按窗口空间自动决定内嵌还是浮层抽屉"，
并把宽度交给用户拖拽，宽度记进配置。

## 二、自适应规则（layout）

| 条件 | 结果 |
| --- | --- |
| `winW ≥ rail + sideW + minChatW` | 侧栏内嵌占位（与 v1.16 一致） |
| `winW < rail + sideW + minChatW` | 侧栏降级为浮层抽屉，不占位 |
| `winW ≥ rail + inspW + minChatW` | 检查器内嵌占位 |
| `winW < rail + inspW + minChatW` | 检查器降级为右侧浮层抽屉 |
| 两者 + 会话区仍放不下（`winW < rail + sideW + inspW + minChatW`） | 检查器让位成抽屉 |
| 两个抽屉同时成立 | 检查器退回内嵌，避免互相压盖 |

关键取舍：抽屉模式下 `sideOcc = inspOcc = 0`，会话区拿到全宽，**不重排消息**，
浮层只是盖在上面 —— 开合抽屉时消息不会"跳一下"。

## 三、可伸缩：拖拽改宽

- 命中区：鼠标贴住侧栏右缘 / 检查器左缘 `±5px`，光标变左右箭头（`IDC_SIZEWE`）。
- 拖拽：实时改宽，松手落盘到 config（`side_w` / `insp_w`）。
- 双击分隔条：复位默认宽度（232 / 272），400ms 内同一条上二次按下即视为双击。
- 钳制：侧栏 180–460、检查器 200–560，且单个面板不超过窗口宽度的 46%，
  窄窗口里抽屉不会把会话区整个吞掉。
- 悬停时手柄变 3px 主色竖条，拖拽中在两处显示短横，明确"这里能拉"。

## 四、遮挡避让

右侧抽屉浮上来会盖住顶栏右端与输入区右端，这一版把被遮部分整体让开：

- 顶栏按钮组（检查器 / 主题 / 设置 / 检索 / 新建）左移 `inspW`
- 工作区入口跟随按钮组移动
- 输入区宽度、消息区裁剪宽、滚动条位置同为 `chatW - inspW`
- 左侧抽屉不需要避让：顶栏按钮与水印都在右侧，被盖住的只有标题区

## 五、抽屉的关闭与开合入口

| 入口 | 行为 |
| --- | --- |
| 左侧 rail 最上方的列表按钮 | 开合侧栏（`toggleDrawer`） |
| 顶栏最右按钮 | 开合检查器（`toggleInspector`） |
| `Ctrl+B` | 开合侧栏 |
| `Ctrl+J` | 开合检查器 |
| 点抽屉外空白处 | 收起对应抽屉，且这一下不穿透到下层控件 |

开合共用 v1.16 的 200ms 缓出动画（`easeOut(1-t³)`），`animStep` 每帧推进进度，
`Timer` 里推进后立刻重排。

## 八、已知限制

- 抽屉当前是"覆盖不重排"，消息区被盖住的部分不可见但仍在原位；若希望抽屉推开而非覆盖，需要另做一版布局模式。
- 左侧抽屉仍从窗口顶部起（覆盖会话区顶栏左端），关闭入口依赖 rail 按钮 / Ctrl+B / 点空白，未在抽屉内单独放关闭按钮。
- 宽度上限 46% 是硬约束，拖到边界后光标继续移动不再加宽。
