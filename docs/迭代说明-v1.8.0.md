# WIN7 Harness v1.8.0 迭代说明

## 一句话

给 Win7 上的 Harness 装上了原生多模态：截图直接粘、图片直接拖、可以只发图不发字，模型看图干活。

## 为什么现在做

之前的排期把多模态放在 v1.6+ 之后，理由是"老模型不支持、要绕 OCR"。现在的实际情况是主流模型基本都支持原生识图（GLM-4V、Qwen-VL、gpt-4o、Gemini、DeepSeek-VL 等），再绕 OCR 就是自找麻烦。所以这版直接按 OpenAI 多模态协议落地，不再做中间层。

## 新增能力

### 1. 三个入口

| 入口 | 操作 | 说明 |
| --- | --- | --- |
| 粘贴 | Ctrl+V | 剪贴板优先取 CF_DIBV5 / CF_DIB 位图，截图工具、微信、QQ、PrintScreen 都能直接粘 |
| 拖放 | 拖到窗口任意位置 | WM_DROPFILES，图片进附件区，非图片自动把路径写进输入框 |
| 选图 | `/image` 或 Ctrl+K 面板 | GetOpenFileNameW 系统对话框，支持多选 |

最多同时附 4 张，缩略图排在输入框上方，点一下即移除。

### 2. 图片处理管线（`internal/core/imageutil.go`）

- 解码：PNG / JPEG / GIF / BMP 走标准库；**剪贴板裸 DIB 手写解码**（`DecodeDIB`），支持 1/4/8/16/24/32bpp、BI_RGB 与 BI_BITFIELDS、top-down / bottom-up
- 缩放：长边超过 1568px 等比缩小，纯 Go 双线性
- 压缩：统一编码 PNG，超过 1.5MB 按 3/4 递降边长直至达标
- 落盘：`%APPDATA%\Win7Harness\attachments\<会话ID>\<sha1前16位>.png`，内容哈希命名天然去重
- 缓存：data URL 与 BGRA 位图均带缓存，翻历史/重发不会重复解码

### 3. 消息协议（`internal/llm/multimodal.go`）

`Message` 新增 `Parts []Part`，并自定义 `MarshalJSON`：

- 无图 → `"content": "文本"`，**请求体与 v1.7 完全一致**，老模型零影响
- 有图 → `"content": [{"type":"text"...},{"type":"image_url",...}]`，标准 OpenAI 多模态格式

刻意没有把 `Content` 改成联合类型，避免动到工具调用、思考内容、会话持久化等所有既有路径。

### 4. 界面（`internal/app/multimodal.go`、`internal/ui/image.go`）

- 输入框上方的附件缩略图，点击移除，最多 4 张
- 消息气泡内按宽高比排一行缩略图（StretchDIBits + HALFTONE 平滑缩放，走 GDI，不需要 GDI+）
- 只发图片时自动补一句占位文本，避免部分服务端拒绝空 content
- 发送按钮在有图无字时也保持可用态

### 5. 上下文与导出

- 重新打开旧会话时，历史图片**不重新上送**（否则每轮请求都要重传 base64，长会话必炸），只在文本里标注"此处原有 N 张图片"
- `/export` 导出 Markdown 时，用户消息的图片以本地绝对路径写成 `![图片](...)`
- 模型不支持视觉时，报错后追加可操作提示（换 glm-4v / qwen-vl-max / gpt-4o 等）

## 兼容性

- 硬约束不变：Windows 7 SP1 起、纯 Go 单文件、零运行库依赖
- 新增 API 全部是 Win7 原生：DragAcceptFiles（shell32）、GetOpenFileNameW（comdlg32）、StretchDIBits / SetStretchBltMode（gdi32）
- 无 CGO，双架构（386 / amd64）交叉编译通过

## 验证

```
go build ./...                                              # 386 全包编译
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build ./...
go test ./internal/llm ./internal/core ./internal/agent ./internal/tools
./build.sh                                                   # 双架构 + PE 校验 + ZIP
```

新增单测：

- `internal/llm/multimodal_test.go`：纯文本请求体不变、带图 content 为数组、仅图无空文本段、工具字段不丢
- `internal/core/imageutil_test.go`：24bpp DIB、CF_DIBV5（biSize=124 且 BI_BITFIELDS 不重复跳过掩码）、缩放、PrepareImage、附件去重、data URL、扩展名判定
- `internal/agent/multimodal_test.go`：无图不产生 Parts、带图生成 data URL、文件缺失不阻塞发送、超过 4 张自动截断

## 已知限制

- 剪贴板 16bpp 按标准 5-5-5 解析，个别老显卡驱动的 5-6-5 会偏色（罕见）
- 图片只存本地，不做 OCR / 不做向量化，检索仍靠文本
- 历史图片重开不重传，因此"让模型回忆上周那张图"这类跨会话追问无法还原原图
- 若以管理员身份运行，资源管理器（非提升）拖入图片会被 Windows UIPI 拦掉，此时用 Ctrl+V 或 /image
